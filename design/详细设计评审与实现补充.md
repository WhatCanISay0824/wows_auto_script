> 状态：评审完成，**详细设计 v0.4 的 Word 文档暂未改写**；本文件是实现阶段的裁决与补充依据。
> 评审方式：两位独立评审员分别从「文档内部一致性」和「算法可实现性」两个角度通读详细设计

## 1. 总体结论

- 详细设计的模块划分、目录结构、状态清单、数据库主表、阶段计划**足以开工**。
- 但存在 4 类必须在编码前裁决的问题：退出流程两套实现、死亡判定阈值多处矛盾、正文引用但
  3.2/3.3 字段表缺失、战斗结束路径跳过 EXITING；另有算法层 8 个 P0（ORB 尺度、坐标链路、
  导航亚像素阈值、阻塞步骤执行、GDI 位图布局、INPUT 结构体、舰船标记性能、死亡投票数学）。
- 裁决原则：**保留状态机作为控制流唯一来源**；步骤序列只描述“单状态内的界面操作”；
  所有阈值/权重/区域进配置；感知只回答“画面上有什么”，世界坐标换算放坐标模块。
- 本次实现按 M0（离线工具与骨架）+ M1（状态机/导航/感知链路，用假数据验证）推进，
  不宣称完成任何实机验收项（详细设计第 16 章 38 项仍待实机回填）。

## 2. P0 裁决

### P0-1 退出流程：状态机驱动，配置只提供按键与特征

详细设计同时给了「声明式 exit_sequence」（3.2/10.1）和「四状态 EXIT_*」（6.1/6.2），
附录 B.2 伪代码又走了第三条（阻塞运行完整序列后直接跳 POST_EXIT_INTERFACE）。

**裁决**：退出由状态机驱动，删除 §3.2 的 exit_sequence 概念（Word 待改）；客户端配置改为
`exit:` 配置组，只提供按键与界面特征：

```yaml
exit:
  menu_key: escape
  menu_open_feature: exit_menu_panel
  return_port_feature: exit_menu_return_port
  confirm_feature: exit_confirm_yes
  port_feature: port_indicator
  direct_exit_feature: null    # 可选：死亡后直接离开战斗按钮
  post_click_wait_ms: 500
```

状态流：`DEAD_PENDING_EXIT`（随机等待 0.8~2.0s）→ `EXIT_MENU_OPEN`（按菜单键、等菜单特征、
点返回港口）→ `EXIT_CONFIRMING`（有确认框则点确认，没有则直接过）→ `EXITING`（等港口或
回港弹窗）→ `POST_EXIT_INTERFACE`（清弹窗）→ `PORT`。
战斗结束（仍存活）路径同样经过 `EXITING`：`BATTLE_ACTIVE → BATTLE_FINISHED`（执行
`result_sequence` 点返回港口）`→ EXITING → POST_EXIT_INTERFACE → PORT`。

### P0-2 死亡判定：统一阈值 + 决策树 + 锁存

统一为配置项（单位秒/毫秒），删除 800ms 与“约两帧”的说法：

- `perception.death.weights`（可配）：hp_bar_absent 0.35、hp_zero 0.25、banner 0.25、
  marker_lost 0.10、spectator_ui 0.05；
- `score_threshold` 默认 **0.65**（原 0.75 在 hp_zero 不可用时不可达）；
- `stable_s`（综合判定稳定时间）默认 **1.0s** —— 2Hz 截屏下约需 3 帧，不是 2 帧；
- `strong_stable_s` 默认 1.5s：`hp_bar_absent` 或 `hp_zero` 稳定达到该时长**直接判死**；
- `banner_latch_s` 默认 5s：死亡提示命中后锁存，避免提示消失后投票回落；
- `marker_lost_stable_s` 3.0s；`ignore_start_s` 5.0s（战斗开始后 5 秒内不判定死亡）；
- `spectator_ui` 命中后进入“观战模式”，不再使用己方血条信号；
- 矛盾只清零对应信号，不清空全部投票（观战界面可能出现队友血条）。

### P0-4 战斗结束路径与超时预算

- 路径改为 `BATTLE_FINISHED → EXITING → POST_EXIT_INTERFACE`；
- `BATTLE_FINISHED` 执行 `result_sequence`（等结算、点返回港口），超时用 `timeouts.battle_finished_s`（60s）；
- `EXITING` 等待港口/回港弹窗，超时用 `timeouts.exit_s`（180s，设计与 13.2 的退出到港口一致）；
- `POST_EXIT_INTERFACE` 只负责弹窗清理，超时用 `timeouts.popup_s`（60s）；
- `timeouts.port_s` 保留为“识别港口界面”的硬上限，由 EXITING/POST_EXIT 共享。

### 算法层补充（来自可实现性评审）

1. **ORB 尺度**：底图与游戏小地图尺度差约 6 倍，超过 ORB 默认金字塔覆盖。地图识别改为
   “按 image_bounds 裁剪底图 → 缩放 bg_scale 到小地图内容宽度 1–2 倍 → 提取 ORB（原图+水平镜像）”，
   缓存 `features.npz` 记录 crop/bg_scale/cv2 版本/ORB 参数/底图 mtime+size；
   输出仿射仍保持“原始底图像素 → 小地图内容区像素”语义（经 `A = A_crop @ S_bg @ T_crop` 合成）。
2. **坐标链路**：`W2M = A @ W2I`、`M2W = inv(W2M)`，全部用 3×3 齐次矩阵；
   8 种方向用常量表；镜像以 image_bounds 中心为轴；`world_to_image` 与 orientation 二选一，
   同时提供时以矩阵为准；运行时识别结果只用于校验声明方向，**不覆盖声明方向**（否则二次旋转）。
3. **GDI 截屏**：`CreateDIBSection` top-down 32bpp（biHeight=-h）+ `BitBlt` 直接进 DIB，
   `np.frombuffer` + `COLOR_BGRA2BGR`；`GetDIBits` 需先把位图从 DC 选回；DPI 用
   `PER_MONITOR_AWARE_V2` 且在一切窗口/DC 之前；黑屏时 `PrintWindow(PW_RENDERFULLCONTENT)` 兜底。
4. **INPUT 结构体**：x64 下 `sizeof(INPUT)==40`，`dwExtraInfo` 用 `ULONG_PTR`（c_size_t）；
   `MOVE_REL` 的单位是鼠标计数（mickey），不是屏幕像素；`MOUSE_WHEEL` 已加入 Action。
5. **StepSequenceExecutor 非阻塞**：`start(steps)` + `advance(now, observation) -> (status, actions)`，
   wait 只记 deadline；主循环每 tick 推进，避免阻塞 10Hz 主循环与 10s 心跳。
6. **导航阈值改像素域**：move_confirm_px=3、stuck_distance_px=3、21s 窗口；到达以
   last_click_target 为基准；速度估计窗口 4s/9 样本。
7. **舰船标记两阶段**：HSV 颜色候选 → 候选窗口局部模板/PCA 求朝向；避免 24 角度全区域扫描。
8. **死亡投票**：见 P0-2。9. **行为采样**：截断正态（sd=0.35×均值），RNG 按相机/攻击/看门狗分流。
10. **战斗 bootstrap**：`BATTLE_ACTIVE` 内部分 bootstrap（识别地图/出生点/标定，最长 15s）与
    navigating 两个阶段；bootstrap 失败不启动导航，但继续死亡监测。
11. **结算优先于死亡**：同一帧同时命中结算与死亡信号时，按 BATTLE_FINISHED 处理。
12. **子流程异常隔离**：导航/行为/死亡检测每 tick 用 try/except 包裹，异常→停止该子流程并记
    `subflow_error`，不影响状态机继续。
13. **单实例**：启动用 `data/.lock`（PID）或 CreateMutexW 防止双开；已存在时退出码 3（实现补充）。
14. **每日场次上限时区**：数据库存 `local_date`（Python 按本地时区计算），禁止 SQLite date() 换算。

## 4. P2 记录（不阻塞，后续处理）

- 模板多尺度可改为“每帧归一化到参考分辨率再匹配”，减少缩放档位依赖；

- `route_end_action` v1 只实现 wait（校验器拒绝 return/random）；
- `exit_method` 统一取值：menu / confirm / direct / recovery / none；
- full_map 导航模式 v1 不实现（校验器拒绝 `navigation.surface=full_map`）；

- 防挂机 AFK 机制本身是未验证假设（V26），M3 前用实机观测决定是否保留开火/消耗品。

## 8. 账号选择与会话间轮换（用户扩展需求，2026-10-30 确认）

详细设计原范围是“单机单账号单窗口、不做多账号管理/账号切换/代登录”。用户明确要求支持
“选择不同的战舰世界账号”，经确认采用 **A + 每账号独立配置与会话间轮换** 口径。

### 8.1 安全边界（不可放宽）

- `accounts.yaml` 只保存**本地别名**（alias）与配置覆盖；**禁止**保存真实账号、密码、令牌、
  验证码、Cookie 等凭据。加载器会递归扫描字段名（password/token/secret/credential/username/
  account_name/email/phone/账号/密码/验证码 等），出现即报 error 并拒绝加载。
- 不自动登录、不代登录、不处理验证码；真实登录和切号由使用者在游戏客户端手动完成。
- 同一时间只运行一个账号、一个游戏窗口；不并发多开。
- 日志与数据库只记录本地别名（`account_alias` 列），不记录任何凭据。

### 8.2 配置结构

```yaml
# config.yaml
accounts:
  rotation_enabled: false        # 是否启用轮换（--rotate 可覆盖）
  rotation_mode: round_robin     # v1 仅 round_robin
  max_battles_per_account: 6
  accounts_file: accounts.yaml

# accounts.yaml
rotation:
  enabled: false
  mode: round_robin
  max_battles_per_account: 6
accounts:
  - alias: alt1                  # 本地别名，不是真实账号
    display_name: 小号一号
    profile: cn360               # 每账号独立客户端配置
    ship_id: placeholder         # 每账号独立船只
    daily_battle_cap: 30         # 覆盖 session.daily_battle_cap
    allowed_hours: ["08:00", "23:00"]
    max_battles_per_session: 6
    enabled: true
    notes: 真实登录请在客户端手动完成
```

`AppConfig.account` 保存当前账号档案；`AppConfig.account_alias` 供日志/数据库使用。
`config_hash` 包含 accounts.yaml 内容与当前别名，不同账号的会话记录可区分。

### 8.3 运行方式

- `python -m src.main --account alt1`：只跑指定账号档案（不轮换）；
- `python -m src.main --rotate`：按 round_robin 依次运行启用账号；每个账号达到
  `max_battles_per_session`（或每日上限/允许时段）后，脚本停止当前会话，在控制台提示
  “请手动切换到账号 X”，使用者完成客户端切号并按回车后，脚本以该账号的配置开始新会话；
- 不传 `--account/--rotate` 时保持原行为（全局 ship.ship_id、单账号）。

### 8.4 数据库与统计

- `sessions.account_alias`、`battles.account_alias` 记录本地别名（可空，向后兼容）；
- 每日场次上限按 `(local_date, account_alias)` 隔离统计；
- `EventSink`/`Database` 的账号参数均为可选，旧调用不受影响。

### 8.5 实现位置

- 契约：`src/config/models.py`（AccountConfig / AccountsConfig / GlobalConfig.accounts / AppConfig.account）；
- 加载与校验：`src/config/loader.py`（load_accounts / load_account / load_app(account=...)）、`src/config/validate.py`；
- 轮换计划：`src/state_machine/accounts.py`（AccountRotator）；
- 主循环：`src/main.py`（--account / --rotate、手动切号提示、每账号独立会话）；
- 状态机：`StateMachine.set_rotation_limit()` 达到上限时以 `account_rotation` 原因停止会话。

## 9. 简化导航：autopilot 模式（用户简化需求，2026-10-30 确认）

使用者提出的简化方案：**不做地图识别、不标定航线**。开局在小地图上点一个目标点，
交给游戏自带自动驾驶，之后不碰 WASD。该方案替代“地图包 + 出生点 + 航线 + ORB 识别”
成为**默认导航模式**（`navigation.mode: autopilot`）；原 waypoints 模式代码保留可选。

### 9.1 目标点口径（用户确认）

- 敌方区域 = 我方出生点关于地图中心的**对称区域**；
- **横坐标固定到中线**：`target = (0.5, 1 - own_y)`（归一化到小地图内容区）；
- `own_y` 取开局时小地图上自身舰船标记的位置（只需标定小地图区域与自身标记模板，
  不需要地图身份、世界坐标、出生点数据、航线数据）；
- 若自身标记不可用：等待最多 10 秒后回退到小地图中心 `(0.5, 0.5)` 并记录警告；
- 之后按 `navigation.autopilot_reclick_s`（默认 60～120 秒随机）重发同一目标点，
  避免到达后停船或卡在岛屿边缘不恢复；不发送任何 WASD/移动按键。

### 9.2 受影响的详细设计章节（v0.5 修订建议）

- §2.1/§3.1/§4/§5.5/§5.8/§7 的“地图识别、出生点识别、航线数据”在 autopilot 模式下
  降级为可选功能（waypoints 模式才需要）；默认运行不需要 `maps/` 数据包；
- §3.3 新增 `navigation.mode/autopilot_target/autopilot_reclick_s/autopilot_offset`；
  `map.auto_identify` 默认改为 false；
- §5.6 小地图标定、§5.7 自身标记识别成为 autopilot 模式的必需标定项；
- §7.1 导航启动前提改为“小地图标定可用 + 战斗 HUD 稳定”，不再要求地图/出生点/航线；
- 第 16 章 V09（小地图是否可点击）成为该模式的关键验证项；V08/V10 仍需要；
  V27/V28（外部底图、ORB 匹配质量）仅在 waypoints 模式下需要。

### 9.3 实现位置与风险

- 实现：`src/navigation/autopilot.py`（AutoPilotNavigator）、`src/state_machine/machine.py`
  的 autopilot 分支、`src/main.py` 装配；
- 配置校验：autopilot 模式下空地图包与缺失自身标记模板降级为 warning；
- 风险：①游戏是否接受小地图点击设置自动驾驶（V09）需实机确认；②自动驾驶可能卡岛/
  避让失败，周期重发只能缓解；③对称目标依赖“双方出生点关于地图中心近似对称”的假设，
  若对局模式破坏该假设会偏离敌区，可用 `autopilot_target: center` 或 `autopilot_offset` 修正；
  ④不识别地图意味着无法针对不同地图调整航线，属于有意的简化取舍。
