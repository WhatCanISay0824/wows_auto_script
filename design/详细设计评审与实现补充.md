> 状态：评审完成，**详细设计 v0.4 的 Word 文档暂未改写**；本文件是实现阶段的裁决与补充依据。
> 评审方式：两位独立评审员分别从「文档内部一致性」和「算法可实现性」两个角度通读详细设计

## 1. 总体结论

- 详细设计的模块划分、目录结构、状态清单、数据库主表、阶段计划**足以开工**。
- 但存在 4 类必须在编码前裁决的问题：退出流程两套实现、死亡判定阈值多处矛盾、正文引用但
  3.2/3.3 字段表缺失、战斗结束路径跳过 EXITING；另有算法层 8 个 P0（ORB 尺度、坐标链路、
  导航亚像素阈值、阻塞步骤执行、GDI 位图布局、INPUT 结构体、舰船标记性能、死亡投票数学）。
- 裁决原则：**保留状态机作为控制流唯一来源**；步骤序列只描述“单状态内的界面操作”；
  所有阈值/权重/区域进配置；感知只回答“画面上有什么”，世界坐标换算放坐标模块。
- 本次实现按 M0（离线工具与骨架）+ M1（状态机/导航/感知链路，用假数据验证）推进，
  不宣称完成任何实机验收项（详细设计第 16 章 38 项仍待实机回填）。

## 2. P0 裁决

### P0-1 退出流程：状态机驱动，配置只提供按键与特征

详细设计同时给了「声明式 exit_sequence」（3.2/10.1）和「四状态 EXIT_*」（6.1/6.2），
附录 B.2 伪代码又走了第三条（阻塞运行完整序列后直接跳 POST_EXIT_INTERFACE）。

**裁决**：退出由状态机驱动，删除 §3.2 的 exit_sequence 概念（Word 待改）；客户端配置改为
`exit:` 配置组，只提供按键与界面特征：

```yaml
exit:
  menu_key: escape
  menu_open_feature: exit_menu_panel
  return_port_feature: exit_menu_return_port
  confirm_feature: exit_confirm_yes
  port_feature: port_indicator
  direct_exit_feature: null    # 可选：死亡后直接离开战斗按钮
  post_click_wait_ms: 500
```

状态流：`DEAD_PENDING_EXIT`（随机等待 0.8~2.0s）→ `EXIT_MENU_OPEN`（按菜单键、等菜单特征、
点返回港口）→ `EXIT_CONFIRMING`（有确认框则点确认，没有则直接过）→ `EXITING`（等港口或
回港弹窗）→ `POST_EXIT_INTERFACE`（清弹窗）→ `PORT`。
战斗结束（仍存活）路径同样经过 `EXITING`：`BATTLE_ACTIVE → BATTLE_FINISHED`（执行
`result_sequence` 点返回港口）`→ EXITING → POST_EXIT_INTERFACE → PORT`。

### P0-2 死亡判定：统一阈值 + 决策树 + 锁存

统一为配置项（单位秒/毫秒），删除 800ms 与“约两帧”的说法：

- `perception.death.weights`（可配）：hp_bar_absent 0.35、hp_zero 0.25、banner 0.25、
  marker_lost 0.10、spectator_ui 0.05；
- `score_threshold` 默认 **0.65**（原 0.75 在 hp_zero 不可用时不可达）；
- `stable_s`（综合判定稳定时间）默认 **1.0s** —— 2Hz 截屏下约需 3 帧，不是 2 帧；
- `strong_stable_s` 默认 1.5s：`hp_bar_absent` 或 `hp_zero` 稳定达到该时长**直接判死**；
- `banner_latch_s` 默认 5s：死亡提示命中后锁存，避免提示消失后投票回落；
- `marker_lost_stable_s` 3.0s；`ignore_start_s` 5.0s（战斗开始后 5 秒内不判定死亡）；
- `spectator_ui` 命中后进入“观战模式”，不再使用己方血条信号；
- 矛盾只清零对应信号，不清空全部投票（观战界面可能出现队友血条）。

### P0-4 战斗结束路径与超时预算

- 路径改为 `BATTLE_FINISHED → EXITING → POST_EXIT_INTERFACE`；
- `BATTLE_FINISHED` 执行 `result_sequence`（等结算、点返回港口），超时用 `timeouts.battle_finished_s`（60s）；
- `EXITING` 等待港口/回港弹窗，超时用 `timeouts.exit_s`（180s，设计与 13.2 的退出到港口一致）；
- `POST_EXIT_INTERFACE` 只负责弹窗清理，超时用 `timeouts.popup_s`（60s）；
- `timeouts.port_s` 保留为“识别港口界面”的硬上限，由 EXITING/POST_EXIT 共享。

### 算法层补充（来自可实现性评审）

1. **ORB 尺度**：底图与游戏小地图尺度差约 6 倍，超过 ORB 默认金字塔覆盖。地图识别改为
   “按 image_bounds 裁剪底图 → 缩放 bg_scale 到小地图内容宽度 1–2 倍 → 提取 ORB（原图+水平镜像）”，
   缓存 `features.npz` 记录 crop/bg_scale/cv2 版本/ORB 参数/底图 mtime+size；
   输出仿射仍保持“原始底图像素 → 小地图内容区像素”语义（经 `A = A_crop @ S_bg @ T_crop` 合成）。
2. **坐标链路**：`W2M = A @ W2I`、`M2W = inv(W2M)`，全部用 3×3 齐次矩阵；
   8 种方向用常量表；镜像以 image_bounds 中心为轴；`world_to_image` 与 orientation 二选一，
   同时提供时以矩阵为准；运行时识别结果只用于校验声明方向，**不覆盖声明方向**（否则二次旋转）。
3. **GDI 截屏**：`CreateDIBSection` top-down 32bpp（biHeight=-h）+ `BitBlt` 直接进 DIB，
   `np.frombuffer` + `COLOR_BGRA2BGR`；`GetDIBits` 需先把位图从 DC 选回；DPI 用
   `PER_MONITOR_AWARE_V2` 且在一切窗口/DC 之前；黑屏时 `PrintWindow(PW_RENDERFULLCONTENT)` 兜底。
4. **INPUT 结构体**：x64 下 `sizeof(INPUT)==40`，`dwExtraInfo` 用 `ULONG_PTR`（c_size_t）；
   `MOVE_REL` 的单位是鼠标计数（mickey），不是屏幕像素；`MOUSE_WHEEL` 已加入 Action。
5. **StepSequenceExecutor 非阻塞**：`start(steps)` + `advance(now, observation) -> (status, actions)`，
   wait 只记 deadline；主循环每 tick 推进，避免阻塞 10Hz 主循环与 10s 心跳。
6. **导航阈值改像素域**：move_confirm_px=3、stuck_distance_px=3、21s 窗口；到达以
   last_click_target 为基准；速度估计窗口 4s/9 样本。
7. **舰船标记两阶段**：HSV 颜色候选 → 候选窗口局部模板/PCA 求朝向；避免 24 角度全区域扫描。
8. **死亡投票**：见 P0-2。9. **行为采样**：截断正态（sd=0.35×均值），RNG 按相机/攻击/看门狗分流。
10. **战斗 bootstrap**：`BATTLE_ACTIVE` 内部分 bootstrap（识别地图/出生点/标定，最长 15s）与
    navigating 两个阶段；bootstrap 失败不启动导航，但继续死亡监测。
11. **结算优先于死亡**：同一帧同时命中结算与死亡信号时，按 BATTLE_FINISHED 处理。
12. **子流程异常隔离**：导航/行为/死亡检测每 tick 用 try/except 包裹，异常→停止该子流程并记
    `subflow_error`，不影响状态机继续。
13. **单实例**：启动用 `data/.lock`（PID）或 CreateMutexW 防止双开；已存在时退出码 3（实现补充）。
14. **每日场次上限时区**：数据库存 `local_date`（Python 按本地时区计算），禁止 SQLite date() 换算。

## 4. P2 记录（不阻塞，后续处理）

- 模板多尺度可改为“每帧归一化到参考分辨率再匹配”，减少缩放档位依赖；

- `route_end_action` v1 只实现 wait（校验器拒绝 return/random）；
- `exit_method` 统一取值：menu / confirm / direct / recovery / none；
- full_map 导航模式 v1 不实现（校验器拒绝 `navigation.surface=full_map`）；

- 防挂机 AFK 机制本身是未验证假设（V26），M3 前用实机观测决定是否保留开火/消耗品。

## 7.6 退出/加载/船只选择的追加口径（2026-10-30 用户确认）

## 8. 账号选择与会话间轮换（用户扩展需求，2026-10-30 确认）

详细设计原范围是“单机单账号单窗口、不做多账号管理/账号切换/代登录”。用户明确要求支持
“选择不同的战舰世界账号”，经确认采用 **A + 每账号独立配置与会话间轮换** 口径。

### 8.1 安全边界（不可放宽）

- `accounts.yaml` 只保存**本地别名**（alias）与配置覆盖；**禁止**保存真实账号、密码、令牌、
  验证码、Cookie 等凭据。加载器会递归扫描字段名（password/token/secret/credential/username/
  account_name/email/phone/账号/密码/验证码 等），出现即报 error 并拒绝加载。
- 不自动登录、不代登录、不处理验证码；真实登录和切号由使用者在游戏客户端手动完成。
- 同一时间只运行一个账号、一个游戏窗口；不并发多开。
- 日志与数据库只记录本地别名（`account_alias` 列），不记录任何凭据。

### 8.2 配置结构

```yaml
# config.yaml
accounts:
  rotation_enabled: false        # 是否启用轮换（--rotate 可覆盖）
  rotation_mode: round_robin     # v1 仅 round_robin
  max_battles_per_account: 6
  accounts_file: accounts.yaml

# accounts.yaml
rotation:
  enabled: false
  mode: round_robin
  max_battles_per_account: 6
accounts:
  - alias: alt1                  # 本地别名，不是真实账号
    display_name: 小号一号
    profile: cn360               # 每账号独立客户端配置
    ship_id: placeholder         # 每账号独立船只
    daily_battle_cap: 30         # 覆盖 session.daily_battle_cap
    allowed_hours: ["08:00", "23:00"]
    max_battles_per_session: 6
    enabled: true
    notes: 真实登录请在客户端手动完成
```

`AppConfig.account` 保存当前账号档案；`AppConfig.account_alias` 供日志/数据库使用。
`config_hash` 包含 accounts.yaml 内容与当前别名，不同账号的会话记录可区分。

### 8.3 运行方式

- `python -m src.main --account alt1`：只跑指定账号档案（不轮换）；
- `python -m src.main --rotate`：按 round_robin 依次运行启用账号；每个账号达到
  `max_battles_per_session`（或每日上限/允许时段）后，脚本停止当前会话，在控制台提示
  “请手动切换到账号 X”，使用者完成客户端切号并按回车后，脚本以该账号的配置开始新会话；
- 不传 `--account/--rotate` 时保持原行为（全局 ship.ship_id、单账号）。

### 8.4 数据库与统计

- `sessions.account_alias`、`battles.account_alias` 记录本地别名（可空，向后兼容）；
- 每日场次上限按 `(local_date, account_alias)` 隔离统计；
- `EventSink`/`Database` 的账号参数均为可选，旧调用不受影响。

### 8.5 实现位置

- 契约：`src/config/models.py`（AccountConfig / AccountsConfig / GlobalConfig.accounts / AppConfig.account）；
- 加载与校验：`src/config/loader.py`（load_accounts / load_account / load_app(account=...)）、`src/config/validate.py`；
- 轮换计划：`src/state_machine/accounts.py`（AccountRotator）；
- 主循环：`src/main.py`（--account / --rotate、手动切号提示、每账号独立会话）；
- 状态机：`StateMachine.set_rotation_limit()` 达到上限时以 `account_rotation` 原因停止会话。

## 7.5 其他用户确认口径（2026-10-30，实机标定相关）

1. **结算页**：胜利与失败结算页面基本一致，共用一套 `battle_results/result_panel/
   result_return_port_button` 模板，不分别标定。
2. **死亡后提前退出**：回到港口时出现的“原战局战报”弹窗**不需要处理**，不为其增加模板；
   若它遮挡港口，按未知弹窗处理（ESC 一次），不点击战报内任何按钮，避免误操作。
3. **船只列表滚动**：使用**鼠标滚轮**滚动（实现为 `Action.move_abs` 把光标移到列表区域 +
   `Action.mouse_wheel`，见 `src/state_machine/ship_check.py`），不拖动滚动条；滚动方向/格数
   由 `ship.yaml` 的 `scroll_direction/scroll_clicks` 配置。
4. **装备校验（信号旗）**：用户确认**只校验信号旗数量为 0**；每场开始前由
   `profile.ship_check_sequence` 执行“切到装备页 → 等待 `信号旗 0/8` 模板 → 切回港口页”，
   任一失败进入 PAUSED。装备界面左侧配件/升级不读取、不点击、不修改。
   经济加成卡保持原样（不主动使用、不摘除，原有就自然耗尽）。`ships/<id>/ship.yaml`
   因此不再配置 `loadout_slots`。
5. **退出流程实测 UI**：ESC → 菜单（离开战斗/设置/帮助/回到战斗）→ 点“离开战斗”→
   确认框“离开战斗?”（是/否/继续战斗）→ 点“是”回港。配置中 `menu_open_feature` 与
   `return_port_feature` 都指向菜单里的“离开战斗”按钮，`confirm_feature` 指向确认框的“是”。
6. **换船**：每次托管的船可以不同。启动时 `--ship-name <船名>` 解析到
   `ships/<ship_id>/` 档案，脚本用鼠标滚轮在港口底部船只轮播条里查找该船卡片并点击选中；
   每艘新船首次使用前需截一次 `card.png`（`calibrate_ship` 工具，约 10 秒）。
   不引入 OCR，因此没有卡片模板的船无法识别。
7. **每船独立血条模板**：不同船的血条面板含不同舰名/舰种，`ships/<id>/hp_bar.png`（+ship.yaml
   的 `hp_bar_template`）用于“血条消失”死亡信号；未提供时自动注销该特征并禁用该信号，
   死亡判定改用死亡提示/结算界面兜底，避免用别的船的模板误判死亡。
8. **禁止交易**：脚本不得售卖、出售或消耗任何船只与装备（包括不能点“出售/拆解/兑换”类按钮）；
   只允许船只列表选择、卡片点击、信号旗空槽校验与消耗品按键（战斗内随机点击）。
   该约束写入 `profiles/cn360/README.md` 与本文档，实现中没有任何售卖/商店相关动作。

## 9. 简化导航：autopilot 模式（用户简化需求，2026-10-30 确认）

使用者提出的简化方案：**不做地图识别、不标定航线**。开局在小地图上点一个目标点，
交给游戏自带自动驾驶，之后不碰 WASD。该方案替代“地图包 + 出生点 + 航线 + ORB 识别”
成为**默认导航模式**（`navigation.mode: autopilot`）；原 waypoints 模式代码保留可选。

### 9.1 目标点口径（用户确认）

- 敌方区域 = 我方出生点关于地图中心的**对称区域**；
- **横坐标固定到中线**：`target = (0.5, 1 - own_y)`（归一化到小地图内容区）；
- `own_y` 取开局时小地图上自身舰船标记的位置（只需标定小地图区域与自身标记模板，
  不需要地图身份、世界坐标、出生点数据、航线数据）；
- 若自身标记不可用：等待最多 10 秒后回退到小地图中心 `(0.5, 0.5)` 并记录警告；
- 之后按 `navigation.autopilot_reclick_s`（默认 60～120 秒随机）重发同一目标点，
  避免到达后停船或卡在岛屿边缘不恢复；不发送任何 WASD/移动按键。

### 9.2 受影响的详细设计章节（v0.5 修订建议）

- §2.1/§3.1/§4/§5.5/§5.8/§7 的“地图识别、出生点识别、航线数据”在 autopilot 模式下
  降级为可选功能（waypoints 模式才需要）；默认运行不需要 `maps/` 数据包；
- §3.3 新增 `navigation.mode/autopilot_target/autopilot_reclick_s/autopilot_offset`；
  `map.auto_identify` 默认改为 false；
- §5.6 小地图标定、§5.7 自身标记识别成为 autopilot 模式的必需标定项；
- §7.1 导航启动前提改为“小地图标定可用 + 战斗 HUD 稳定”，不再要求地图/出生点/航线；
- 第 16 章 V09（小地图是否可点击）成为该模式的关键验证项；V08/V10 仍需要；
  V27/V28（外部底图、ORB 匹配质量）仅在 waypoints 模式下需要。

### 9.3 实现位置与风险

- 实现：`src/navigation/autopilot.py`（AutoPilotNavigator）、`src/state_machine/machine.py`
  的 autopilot 分支、`src/main.py` 装配；
- 配置校验：autopilot 模式下空地图包与缺失自身标记模板降级为 warning；
- 风险：①游戏是否接受小地图点击设置自动驾驶（V09）需实机确认；②自动驾驶可能卡岛/
  避让失败，周期重发只能缓解；③对称目标依赖“双方出生点关于地图中心近似对称”的假设，
  若对局模式破坏该假设会偏离敌区，可用 `autopilot_target: center` 或 `autopilot_offset` 修正；
  ④不识别地图意味着无法针对不同地图调整航线，属于有意的简化取舍。

### 9.4 实机确认：必须先按 M 打开放大地图再点选（2026-10-30，待修复）

实机联调确认玩家正确交互为：**按 `M` 打开放大的全屏地图 → 在地图上左键点选目标点 → 关闭地图**。
直接在战斗画面右下角的小地图上点击**不会**设置航向；当前实现 `AutoPilotNavigator` 直接点击
小地图坐标，因此 3 次点击均无效、船停在原地（证据见 `docs/实机问题记录.md` ISS-001）。

- 该差异属于 V09 实机验证结果，原“小地图可点击”假设不成立；
- 后续修复方向：`M` 打开地图 → 等待地图界面稳定 → 按**全屏地图视图**坐标（需重新标定/换算）
  点击目标 → 关闭地图（`M`/`Esc`）返回战斗；并验证地图界面期间的输入隔离、按键释放、目标线出现；
- 按用户要求，2026-10-30 仅记录、暂不修改代码；修复前需补一张实机全屏地图截图用于坐标标定。

### 10.1 ISS-001 自动驾驶改为「M 全屏地图点选」

- 默认交互：按 `M` 打开全屏地图 → 等待地图界面就绪 → 在**全屏地图内容区**点击目标 →
  再按 `M` 关闭地图返回战斗；旧的“直接点小地图”路径保留为可配置降级项。
- `navigation.surface` 扩展为 `full_map`（autopilot 默认）| `minimap`（旧交互，降级/兼容）；
  `surface` 只描述 autopilot 的点击面，waypoints 旧模式不受影响。
- 目标归一化坐标沿用 9.1 的 `(0.5, 1 - own_y)`；屏幕坐标由 `navigation.full_map_rect`
  （全屏地图**内容区**，相对窗口客户区的归一化矩形）换算；开关按键用
  `navigation.full_map_toggle_key` 对应的 `keys.yaml` 动作（已存在 `full_map: m`）。
- 新增导航配置（默认值）：`full_map_open_wait_s=1.0`、`full_map_close_wait_s=0.4`、
  `full_map_verify_s=8.0`、`full_map_retry=2`、`autopilot_verify_min_move_px=3.0`、
  `autopilot_verify_min_speed=0.5`（m/s）。`full_map_rect` 由 2026-10-30 两张实机 M 地图截图
  （`屏幕截图 2026-10-30 211242.png` / `211253.png`）标定后写入 `config.yaml`。
- 输入隔离：地图打开到关闭完成前，autopilot 以 `blocks_behavior` 通知状态机暂停随机行为；
  开/关地图的按键按 down/up 同批提交，由输入线程保证释放；全程不发送 WASD；
  打开地图期间若检测到暂停/失焦，autopilot 重置到等待态，不补发旧点击。
- 点击后验证：关闭地图后等待 `full_map_verify_s`，观察自身标记位移或船速是否超过阈值；
  成功记 `autopilot_confirmed`，失败记 `autopilot_verify_failed` 并重试 `full_map_retry` 次；
  仍失败时按 `surface=minimap` 旧路径降级一次并记录 warning，不重复盲点同一目标。
- 全屏地图“自动整图显示/居中”是需要实机验证的假设：若点击后无位移，按失败处理并停止升级，
  不声称已修复（V09 新口径）。验收：进战斗 ≤5s 内发出 M→点选→关闭，船速>0 且向目标区域移动，
  连续 3 场；未实机前只写“离线实现完成/待实机”。

### 10.2 ISS-002 血条归零证据与提前退出硬门禁

- 判零算法改为**与颜色无关的血条填充宽度**：在 `battle_hud.hp_bar_region`（整条血条区域）内
  逐列统计“填充像素”（高饱和度/高亮度的绿/黄/红/橙都算填充，深色底不算），
  填充比例 = 有效填充列数 / 有效列数；绿色 HSV 范围降级为辅助证据，不再单独代表血量。
- `battle_hud` 新增配置：`hp_bar_empty_max_ratio`（默认 0.02，低于=空）、
  `hp_bar_alive_min_ratio`（默认 0.10，高于=存活）、两者之间=无法判断；
  `hp_bar_confirm_frames`（默认 2）、`hp_bar_evidence_ttl_s`（默认 1.0）。
- `DeathSignals` 增加：`hp_fill_ratio: float | None`、
  `hp_evidence: "alive" | "zero" | "unknown" | "unavailable"`、
  `exit_authorized: bool`、`evidence_at: float`（最近一次“确认归零”证据的时间戳）。
- 退出授权 `exit_authorized` = 血条区域有效且连续帧 `hp_evidence == "zero"` 达标 +
  最近证据在 TTL 内 + 未出现矛盾证据（存活帧/新鲜帧缺失/区域或模板异常）。
  `banner` / `hp_bar_absent` / `marker_lost` / `spectator_ui` 继续参与日志与投票，
  但**不得单独授权提前退出**。
- 状态机门禁：`BATTLE_ACTIVE` 只有 `death.exit_authorized` 才进 `DEAD_PENDING_EXIT`；
  进入退出菜单前再次校验授权与证据新鲜度；等待期间出现存活/未知证据时撤销尚未执行的退出动作
  并回 `BATTLE_ACTIVE`；无法确认归零时等待自然结算（`BATTLE_FINISHED` 路径仍可用）。
- 战斗内未知画面不自动发送 ESC：`ERROR_RECOVERY` 在战斗上下文内只重试识别或暂停；
  退出菜单键只用于已授权的退出流程；导航开关地图只用 `M`，不借用 ESC。
- 诊断：保存血条裁剪/填充比例/证据状态；GUI 与日志不得把识别比例显示成实际血量。
- 样本约束：`20261030_235258_death.png`（32,794/41,200，黄色）与满血绿色样本必须判存活；
  红色 0 血样本（212021）按空条处理；红色但非空的残血样本必须判存活；
  模板缺失/遮挡/未知画面不授权退出。离线用合成图 + 本地实机样本（不存在时 skip）回归。

### 10.4 ISS-004 暂停/停止的统一输入门禁

- `InputExecutor` 增加输入门禁：暂停/停止/紧急停止时关闭门禁 →
  拒绝新业务动作（统计 rejected）、`epoch+1` 使在途/排队批次失效、清空待执行业务动作、
  入队“释放所有键鼠”控制动作并由输入线程执行；恢复时重新打开门禁。
- `release_all()` 语义改为“取消 + 释放”（清队列 + epoch + 释放），保持既有调用兼容；
  新增 `close_gate_and_release()`（非阻塞，供安全监控/暂停入口）与 `open_gate()`。
- 状态机进入 `PAUSED` / `STOPPING` 关闭门禁，`PAUSED` 恢复时打开；
  恢复后只接受重新识别画面生成的新动作。
- 验收：在途批次、排队批次、重复暂停/恢复；释放动作执行后不得再执行暂停前遗留业务动作。

### 10.5 ISS-005 F12 与心跳超时独立切断输入

- `SafetyWatchdog` 装配事件回调：F12 / 心跳超时在监控线程内**直接**调用
  `executor.close_gate_and_release()`（线程安全、非阻塞，只入队释放动作），
  不再等待主循环；状态机转移、日志收尾仍由运行线程负责，监控线程不发送游戏操作。
- 停止/暂停请求仍写 `StopController`；主循环同步后完成状态机转移。
- 记录事件时间、门禁关闭与释放计数，GUI 后续可显示“停止已确认释放”。
- 验收：主循环被人为阻塞时触发 F12，独立输入线程在 ≤1s 内释放键鼠且拒绝新动作。

### 10.6 ISS-006 暂停状态同步与恢复保留战斗上下文

- 所有暂停来源统一：状态机暂停同时写共享 `StopController`，F11 清除控制器后由主循环转发恢复；
  自动失焦暂停、心跳暂停、装备/选船校验失败、GUI 暂停共用同一来源与恢复路径。
- 恢复分流：
  - **当前会话战斗内暂停**（本进程已创建 `battle_id`）：恢复时重新识别画面。仍在战斗且存活证据
    未确认归零 → 回 `BATTLE_ACTIVE`，保留 `_battle_id`/场次记录，重启 autopilot/behavior
    （随机行为用原种子重建，不覆盖数据库随机档案）；已出现结算 → `BATTLE_FINISHED`；
    已回港口 → 写结束记录后 `PORT`；死亡证据已确认 → `DEAD_PENDING_EXIT`。
  - **新进程在战斗中**（INIT 检测到 `LOADING/BATTLE_ACTIVE/BATTLE_FINISHED/DEAD_PENDING_EXIT`）：
    `restart_mid_battle` 暂停后**不接管**已有战斗；F11 只在检测到结算或港口时恢复，
    否则保持暂停并记录“不接管上一场战斗，等待自然结算”。
- 场次收尾：任何离开战斗上下文但未走完结算的路径（INIT/PORT/STOPPING/恢复失败）必须写
  `end_battle("aborted"/"interrupted")` 并结束该场截图目录，不得静默清空 `battle_id`。
- 验收：港口、排队、战斗、装备失败、心跳暂停五类恢复；重复恢复不新建/丢失场次。

### 10.7 ISS-007 选船：确认已选中后再开局

- 流程改为：查找目标卡片 → 唯一可信候选则点击 → 等待新帧 → 用**已选中证据**确认当前船为目标船
  → 检查该船信号旗（装备页 `信号旗 0/8`）→ 加入战斗。
- 已选中证据：优先使用船只档案/profile 配置的 `selected_feature`（选中高亮/详情面板模板，
  由标定工具生成）；未配置或无法可靠匹配时，暂停并提示补标定，**不得**把“卡片可见”当作“已选中”。
- 轮播搜索：空 `ship_selection_sequence` 只表示“不需要打开列表”，**不取消**滚动预算
  （修复 `_start_selection` 把 remaining 清零的问题）；从可确认起点或双向覆盖查找，
  端点以列表画面不再变化判定，受总滚动次数/超时约束；多个相似可信候选时暂停并展示候选。
- PORT 阶段顺序：先确认已选中目标船，再做信号旗校验，避免用上一艘船的装备页结果开局。
- 验收：目标可见但未选中、目标在屏外、目标不存在、选中后信号旗非零四类；至少两艘船交替实机。

### 10.8 ISS-008 会话异常也执行统一清理

- 运行时构建支持部分失败回收：日志、截屏、事件线程、输入线程按创建顺序登记；
  任一步失败回收已创建资源后再抛错，不遗留线程。
- 每个账号的 `_build_runtime()` + `_run_session()` + `_teardown()` 用 `try/finally` 绑定，
  正常返回、异常、`KeyboardInterrupt`、构造失败都走幂等清理；清理完成前不启动下一次运行。
- 异常原因写日志并作为退出码/事件返回；GUI 后续展示具体原因。
- 验收：构造各阶段、感知、状态机、运行循环注入异常；已创建资源全部回收、输入释放。

### 10.9 ISS-009 输入线程连续失败后上层进入暂停

- 达到连续失败阈值后：置 `failed`、清空队列、**由输入线程立即执行一次释放**并记录；
  后续业务动作一律拒绝。
- 运行线程每轮检查 `executor.failed`，转入 `PAUSED`（原因 `input_failed`，带最后错误）；
  恢复前必须调用 `executor.reset_after_failure()`（清理失败计数/重新启动输入线程/打开门禁）成功，
  否则保持暂停并提示排查输入后端。
- 验收：连续失败假后端 → 无业务输入、上层及时暂停、释放尝试、原因可见。

### 10.13 截屏冻结帧修复（ISS-011，2026-10-31 实机发现）

- 现象：无边框全屏下，游戏窗口 DC 的 ``BitBlt`` 返回 DWM 缓存旧表面、
  ``PrintWindow(PW_RENDERFULLCONTENT)`` 对 flip-model 交换链返回静态帧；旧实现只在黑屏时兜底，
  因此“有效但冻结”的画面被当作正常帧，装备页切换后状态机仍看到港口页，`loadout_signal_flags`
  永不命中（实机日志连续三次 `loadout_check_failed`）。
- 修复：新增配置 ``perception.capture_method: auto | window | screen``（默认 ``auto``）。
  ``auto`` 在“客户区覆盖虚拟屏幕 ≥95%、原点误差 ≤2px、游戏前台”时优先桌面 DC（``GetDC(0)``）
  按客户区屏幕位置 ``BitBlt``，成功后固定桌面截屏；失败回退旧窗口 BitBlt/PrintWindow。
  ``window`` 保持旧行为，``screen`` 强制桌面截屏（远程/特殊环境）。
- 实现：``src/perception/capture.py`` 新增 ``GdiFrameSource.grab_screen``、
  ``is_fullscreen_client_rect()`` 与 ``GdiCapture(capture_method=...)``；``main.py`` 与
  ``check_env.py`` 传入配置；``config.yaml`` 增加 ``perception.capture_method``。
- 证据：实机新路径 ``screen_only=True``；桌面装备页模板 ``loadout_signal_flags`` 命中 0.999
  （旧路径 0.278 永不命中）；离线新增桌面截屏/冻结帧/回退测试，全套 `pytest` 754 项通过。
- 待验证：用户重启脚本后能通过装备页校验并完成一场联合作战（端到端实机验收）；
  多显示器/窗口化/远程桌面场景沿用旧路径或显式配置 ``window``/``screen``。
