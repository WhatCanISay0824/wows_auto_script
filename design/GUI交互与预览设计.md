# GUI 交互与预览设计

日期：2026-10-31。状态：浅色桌面界面、数据查询、小地图展示、本场目标替换及 GUI 前台协作已实现，游戏内效果待实机验收。

本文确定托管台的界面布局、性能监测、数据展示和运行中目标点修改。界面以 Codex 一类桌面工具的结构为参考：左侧导航、中央工作区、侧边监测区和底部日志。所有预览数值和地图均为示例，不来自当前运行中的游戏。

运行服务、单实例、输入释放、日志桥接、船卡导入等基础契约参见 [GUI 界面设计文档](GUI界面设计文档.md)。涉及页面组织、视觉表现、前台焦点、性能面板、数据面板和目标点修改时，以本文为准。运行服务与界面已经接线；截图更新和选点使用现有运行线程，不另建游戏输入通道。离线验证通过不代表实机可用。

## 1. 目标与约束

- 提供性能、数据、日志和设置四个模块，运行控制始终可用。
- 默认页面展示托管数据和小地图，性能摘要、最近日志同时可见。
- 使用平面背景、细分隔线、小幅圆角和系统字体。颜色只用于选择状态、地图标记和真实异常。
- 不添加欢迎语、口号、装饰插画、宣传文字、常驻教程和重复提示。
- 标签、数值、单位、实际状态、操作结果和必要错误属于功能内容，必须保留。
- 所有数据保存在本地。GUI 不读取游戏内存或网络数据，不直接发送游戏键鼠输入。
- 继续采用共享运行服务、唯一输入执行线程和现有游戏状态机，不因界面交互重启托管。

## 2. 窗口与布局

正式桌面窗口建议初始大小 1280 × 820，最小大小 1024 × 720。最小尺寸下可缩减记录行数、折叠次要字段；不缩小主要文字或隐藏停止按钮。预览额外适配窄屏，以方便在对话中查看，不代表正式产品包含移动端。

| 区域 | 内容与职责 |
| --- | --- |
| 左侧导航 | 数据、性能、日志、设置四个入口；底部保留当前客户端与船只摘要 |
| 顶部运行栏 | 当前页面、脚本生命周期、游戏流程；启动、暂停或恢复、停止 |
| 中央工作区 | 根据左侧入口展示数据、详细性能、完整日志或设置 |
| 右侧性能区 | 全机 CPU、物理内存、可用内存、脚本进程内存、截图耗时和监测时间；保护阈值状态 |
| 底部日志区 | 最近结构化日志；进入日志页后让中央区域展示完整日志，避免重复堆叠 |
| 底部状态行 | 输入状态、画面更新时间和当前目标反馈；停止中显示释放与清理进度 |

数据是默认入口，显示右侧性能摘要。性能、设置和日志页使用完整工作区；日志页收起底部日志摘要。数据页在较矮窗口中纵向滚动，地图保持约 300 × 300，不挤压顶部控制栏。各区域用直线分隔，不使用多层卡片和阴影。

## 3. 视觉规则

| 项目 | 规则 |
| --- | --- |
| 主题 | 正式界面本轮采用浅色预览：白色工作区、浅灰侧栏；预览中的深色外观尚未接入 |
| 字体 | Segoe UI / Microsoft YaHei UI；正文约 14 px，次要字段约 12 px，区域标题约 14–16 px |
| 字重 | 正文常规，标题与选中项中等；不使用夸张大标题 |
| 间距 | 8 px 基础步长；区域内边距通常 16 px，密集日志行使用较小间距 |
| 控件 | 约 32 px 高；选择控件保留明确标签；所有按钮有键盘焦点样式 |
| 状态 | 文字表达含义，颜色作为补充；不只用圆点表示运行、失败或停止 |
| 动效 | 只使用短暂的交互反馈，不添加循环装饰动画 |

界面结构与控件表现需要在 Tkinter + ttk 中定制样式，不能继续把系统默认主题当作视觉验收标准。当前仍保留 Tkinter 方案，不因绘制预览更换框架或增加前后端服务。正式界面已按预览调整布局、字号和间距。Tk 按钮保留原生绘制，边角与浏览器预览存在细微差异。

## 4. 数据面板

### 4.1 会话数据

顶部展示完成场数、今日场数、托管时长三项摘要，附带已知上限；其下展示船只、账号别名、会话和场次编号。客户端位于侧栏底部，游戏流程位于摘要右上。

历史记录字段为场次、开始时间、时长和结果；按当前账号读取最近 30 场。缺少结束时间时，时长显示“—”。结果使用现有数据库能够证明的语义：完成、检测到死亡、中断；正在运行的场次显示进行中。不得把 `finished` 推导成胜利，不展示没有采集来源的胜率、伤害、经验和收益。

现有 SQLite 表没有每场船名字段。第一版历史表不新增“船只”列，也不把当前选船回填为历史船只。当前船只只显示在当前会话摘要中。增加历史船只记录需另行确认存储设计。

统计由后台只读查询或已发布快照提供；不在 GUI 主线程查询数据库，不共享日志线程的写连接。写入继续由现有 EventSink 负责，不增加数据库表和迁移。

### 4.2 小地图

- 从既有截图链路取得最新帧，只裁剪已标定的小地图内容区；GUI 不再建立独立全屏截图循环。
- 复用现有约 2 Hz 截图，只保留最新图像，不积压图像队列。
- 刷新率是设计目标，需结合实测截图开销调整，不能宣称已经达到。
- 等比例展示，显示原游戏地图信息；叠加本场用户目标标记，不把它画成已经验证的游戏航线。
- 保留最近帧时间并显示真实帧龄。同场地图允许直接选点，执行前必须取得新的游戏战斗画面；无战斗画面时显示“无战斗画面”。
- 当前全屏截图依赖游戏前台。GUI 前台等待时保留最近地图并显示帧龄，不继续发布可能被工具遮挡的游戏画面；因此当前不支持长期停留 GUI 时持续实时更新。
- 地图放大、旋转、内容区标定失效或窗口几何变化时，禁止继续沿用旧坐标。

当前可读取的 `logs/env_check_minimap.png` 实际为港口裁剪，不能作为战斗小地图。预览使用明确标注的示意地图，不把它称为实机截图。

### 4.3 修改航行目标

已确认采用单目标点替换。用户直接点击小地图即可提交本场新目标，不需要暂停、停止或重启托管。“更改目标”按钮用于将焦点移到地图，不是点击地图的前置步骤。

运行中且处于战斗活动状态、具有同场有效图像、坐标标定有效并且没有停止请求时允许操作。因窗口丢失、失焦或暂不可用而暂停时，也允许点击本场地图，明确请求返回游戏并应用目标；执行前重新验证游戏窗口和新战斗帧。手动暂停、异常暂停、停止、结算和死亡退出时禁用。

命令采用归一化地图坐标，附带 `battle_id` 和 `frame_id`；运行线程保存对应帧的时间和窗口矩形，并复核当前场次和坐标依据。显示帧不设五秒提交时限，提交后的请求最多等待 30 秒。GUI 只提交意图，运行服务再次检查上下文，并通过现有导航器和输入线程执行：

1. 接受新目标，替换尚未执行的旧请求；已经开始的地图操作先到达可取消或可完成的边界，禁止叠加开图按键。
2. 返回游戏前台，取得提交后的新画面并确认仍为本场战斗，再串行执行 M 打开全屏地图、等待、映射点击目标、M 关闭地图与结果检查。用户目标必须走全屏地图路径，缺少全屏地图标定或 M 按键映射时拒绝执行。
3. 地图操作期间抑制与其冲突的随机行为，截图、监测、记录和停止监听继续运行。
4. 本场后续自动重设使用用户目标；禁止默认目标策略在下个周期覆盖它。
5. 本场结束、会话结束或新场次开始时清除覆盖，下一场恢复默认策略。

界面区分目标接收、交给导航器、已发出、激活文字和已检测到移动，并显示具体失败原因。船只位移或速度证据只证明船在移动，不证明已经沿用户目标航行。请求等待最多 30 秒，超时、跨场或窗口矩形变化时取消。

导航器通过 `replace_target()` 接受本场目标，同场恢复保留，新场次清除。当前小地图标定对应 2560×1600 游戏画面中右下角约 376×376 的区域；在游戏中调整小地图大小后需要重新标定。全屏地图按已标定的外接矩形换算坐标，实机地图存在梯形透视。需要实机检查方向、内容区边界与选点误差；本轮不新增透视标定算法，实际精度未验证。

自动策略在开图前从新鲜小地图中筛选水面终点，避开陆地及未知像素并留出离岸距离，未检测到移动时更换失败候选。无法取得可靠水面候选时暂缓默认选点并记录原因。用户明确指定的目标保持原坐标。水面终点不等同于完整航线可达，完整规划仍交给游戏自动驾驶。

不支持多途经点、画线、自动绕岛或 GUI 自行路径规划。地图中的示意直线只连接船位和目标，不代表游戏最终规划出的航线。选点落在陆地等不适用位置时，不宣称能够自动识别或修复，应依据游戏反馈报告结果。

### 4.4 改动范围判断

只读小地图可以复用已有截图和内容区标定，在共享运行服务完成后作为较小的展示扩展。目标替换还涉及前台焦点、导航目标覆盖、串行输入和确认反馈，属于独立的交互扩展，不能按“增加一个点击回调”估算。

本轮已实现只读展示和单目标替换的运行通道；实际地图坐标精度和游戏选点效果由实机验收确认。

## 5. 前台焦点与持续托管

用户已确认：切到本工具查看数据、日志、性能或设置时，托管会话保持运行，仅暂缓需要游戏前台的键鼠动作；切到其他应用仍按原规则暂停。

该规则需要同步调整运行循环中的失焦判定和输入执行前的前台校验，不能简单关闭全局的 `pause_when_unfocused`。

- 按前台窗口所属进程识别本工具，不按窗口标题模糊匹配其他应用。
- 本工具前台时，不把生命周期或游戏流程改成 PAUSED；状态行显示“等待游戏前台”。
- 前台切换期间立即释放输入，再用最多 0.5 秒等待状态稳定；切到本工具后保持 GUI 等待，持续停留其他应用才进入窗口暂停。
- 已按下键鼠通过唯一输入线程释放，未执行业务批次失效；不在返回游戏后集中补发。
- 心跳、过载采样、记录查询和界面更新继续进行；依赖游戏前台的感知与游戏动作等待返回游戏。等待不触发游戏操作步骤的错误超时；不累计随机行为等待期间的漏发动作。
- 用户只查看界面时不反复抢回焦点，游戏本身的自动驾驶可继续运行，但脚本不承诺期间所有战斗动作持续执行。
- 用户提交目标时，允许一次切回游戏的尝试；失败则保留可见的失败状态，不反复抢焦点。只有游戏前台和当前画面重新验证通过后才恢复新业务输入。
- 停止、F12、心跳异常、输入失败或切换到其他应用时，原有安全流程优先，禁止因目标请求自动恢复。
- GUI 前台等待属于输入调度状态，不能用持续伪造心跳掩盖运行循环阻塞。

## 6. 性能面板与过载保护

### 6.1 第一阶段：监测展示

用户已确认先展示性能；过载判定阈值已于 2026-10-31 确认，见 [GUI 过载保护阈值设计](GUI过载保护阈值设计.md)。预览稿仍保留“保护阈值：待确定”的示例文案；正式实现默认 `overload.mode: monitor`，显示“保护阈值：监测中（不自动停止）”，在实机标定并切换到 `pause_stop`/`stop` 后才显示“保护已启用”。任何情况下不得把示例数据达到某一数值解释为自动停止条件。

建议每秒采样全机 CPU、物理内存占用和可用内存；脚本进程内存、截图耗时和主循环耗时用于定位脚本开销。CPU 的首次采样需要时间差，首个值显示“—”，不写成 0%。GPU、温度和显存不作为首版必备数据，避免为展示增加驱动和传感器依赖。

正式实现优先评估现有 Windows API 与已有 ctypes 方式，不预先增加依赖。监测不可用时显示“不可用”和具体原因，不能将缺失值视为健康。性能采样不在 GUI 主线程执行，关闭或切换面板不能影响后台监测。

### 6.2 过载停止的目标行为

阈值、持续时间和监测失效策略已于 2026-10-31 确认并落入 [GUI 过载保护阈值设计](GUI过载保护阈值设计.md)：判定只接受 Commit 提交内存耗尽与清醒状态下的多秒级调度饥饿，CPU/物理可用内存/心跳/帧龄只告警；单次峰值不自动等同过载；实施先 `monitor` 标定，再启用保护性暂停与优雅停止。

后续启用后，后台监测不依赖 GUI 轮询和日志渲染，触发时走已有的独立停止路径：关闭输入门禁、使旧动作失效、清空待执行业务动作、请求唯一输入线程释放键鼠，并令运行服务进入 STOPPING。

收到输入释放及必要清理确认后，才能显示“已停止 · 电脑过载”。在此之前显示“停止中”；无法确认时显示具体错误。记录指标、阈值、持续时间、触发时间和释放结果。游戏继续运行，不杀游戏或其他进程；负载恢复后不自动重启。

整机已经严重卡死时无法保证采样线程和释放线程获得调度，不作无条件的停止时延承诺。原有 F12、心跳监控和输入失败处理继续保留。

## 7. 日志面板

常驻区域显示最近日志，字段为时间、级别、模块和内容；日志页增加级别、关键词、当前场次筛选和自动滚动控制。阅读历史日志时不强制滚回末尾。

界面最多保留 2000 条，完整日志继续写本地文件。过滤和切页不改变日志采集，不清空文件。错误只显示真实原因，不逐帧弹窗或自动抢焦点。

预览只提供示例日志过滤与目标请求反馈，不提供假装已经接入系统的“打开文件”“导出”或“执行工具”按钮。

## 8. 设置面板

设置按运行、船只、工具三组组织：

| 分组 | 字段或操作 |
| --- | --- |
| 运行 | 客户端、本地账号别名、本次场次上限、启动时暂停、日志级别；会话与每日安全上限只读 |
| 船只 | 船名输入与已登记档案候选、首次导入船卡入口；不做 OCR 或自动猜选 |
| 工具 | 已有船卡、界面区域、自身标记标定与环境检查入口；高级参数仍由现有 YAML 管理 |
| 显示 | 全屏显示开关（只改变 GUI 窗口显示，运行中可切换；纯内存态，不写 config.yaml；与其它控件同样式） |

所有会影响托管行为的配置在运行中只读，停止且清理完成后才能修改，启动前统一校验。目标替换是经过授权的本场临时命令，不属于运行中修改 YAML。

桌面实现使用随系统 DPI 缩放的磅数字体，地图根据页面可用宽高扩展，记录区利用剩余高度，小窗口纵向滚动。客户端只有一个选项时显示为文本；账号只有默认项时显示为文本，不超过四个选项时直接单选。船名与档案候选共用一个可输入选择框，候选包含档案编号以区分同名船。设置表单限制最大宽度，避免全屏时输入框过度拉伸。

同场暂停或 GUI 等待期间保留最近地图与原始截屏时间，场次结束或更换后清除。地图不可用时显示实际原因；全屏地图关闭后取得新帧即可更新小地图，不必等待航向移动验证结束。GUI 等待期间，同场地图仍可提交目标，执行前重新取得战斗画面并复核。

不增加凭据输入框，不扩大账号权限，不加入本轮无需求的批量任务和远程管理。标定、船卡保存和正式工具执行不在本轮预览中模拟为已完成能力。

## 9. 运行控制

启动仅在停止并清理完成时可用。运行中显示暂停，暂停后显示恢复。停止按钮在运行或暂停期间始终可用，不先弹确认框；停止中禁用重复请求，等待输入释放与清理反馈。

停止只结束脚本控制和记录，不向游戏发送离开战斗或关闭游戏命令。F12 继续作为不可恢复的紧急停止。等待手动切号、异常清理和窗口关闭沿用基础文档的契约，不在此次界面设计中扩展其权限。

提前死亡时按退出菜单回港，回港后随机等待 3～10 秒，再进入既有选船和加入战斗流程；同一场间等待只采样一次，暂停恢复不重置倒计时，首场不等待。存活结算优先等待并点击“继续战斗”，直接进入下一场；等待窗口结束仍未识别到继续按钮时，保存诊断信息并尝试回港。会话上限优先于继续战斗。

## 10. 预览范围与验收

预览包括四个模块切换、示例日志筛选、单目标点选取反馈、暂停与恢复、停止与重新启动，以及停止后修改基本运行选项。所有行为仅改变预览内存，不连接游戏、系统监测、真实输入或数据库。

| 验收对象 | 判据 |
| --- | --- |
| 视觉与布局 | 四个模块均可访问，默认数据页同时可见地图、记录、性能摘要和日志；无装饰文案和重复提示 |
| 预览交互 | 模块切换、筛选、选点和运行控制可操作；手动暂停或停止时不能选点；窗口暂停时可提交本场目标并请求恢复；更改目标不主动暂停托管 |
| 边界诚实 | 预览标注示例数据；地图为示意；保护阈值待定；已发出目标不等于游戏已确认 |
| 显示检查 | 1024 px 与 1280 px 桌面宽度，以及 375 px 和 320 px 对话窄屏无水平溢出；明暗外观可读 |
| 实施前验证 | 确认 GUI 前台时截图新鲜度、目标点坐标精度、输入互斥、F12 优先级、单目标覆盖持续性和新场次清除 |
| 过载保护验收 | 阈值确认并实现后，分别验证持续过载、瞬时峰值、GUI 阻塞、运行循环阻塞及监测失败；模拟测试不能代替实机释放检查 |

过载规则见 [GUI 过载保护阈值设计](GUI过载保护阈值设计.md)，默认仍为 monitor。数据、小地图与单目标命令已接线，GUI 前台时不持续实时截取游戏。地图选点、开局巡航和输入释放的实际效果仍需实机验证。全屏显示开关是设置页的 GUI 显示选项，不改变托管与游戏流程。
