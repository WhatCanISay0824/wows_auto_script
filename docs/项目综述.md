## 1. 这是什么

一个在 Windows 本机运行的《战舰世界》（World of Warships）**联合作战（PvE）挂机脚本**，
目标是把「港口 → 选船 → 校验 → 排队 → 进战斗 → 自动航行/随机开火 → 死亡退出 → 回港 → 下一场」
整条链路自动化。

项目只用于**本地自动化技术研究**：

- 只通过**截屏 + 模拟键鼠（SendInput）**工作；
- **不读取游戏内存、不修改客户端文件、不抓取/篡改网络数据**；
- 界面识别用模板匹配，**不引入 OCR**；地图识别（旧 waypoints 模式）用 ORB 特征匹配；
- 界面参数、按键、按钮、区域、船只全部做成配置，不写死在代码里；
- 建议只用**可弃小号**，并限制每日场次与单次运行时长；不要公开传播或用于商业用途。

## 2. 功能概览

| 功能 | 说明 | 状态 |
| --- | --- | --- |
| 全自动会话流程 | 港口 → 选船（确认已选中）→ 加入战斗 → 排队 → 战斗 → 结算（优先“继续战斗！”直接下一局，否则回港）→ 下一场 | 实机联调中 |
| 简化 autopilot | 开局按 `M` 打开全屏地图点选「敌区对称点」启用游戏自带自动驾驶，之后不碰 WASD；目标点 `(0.5, 1 - own_y)`，60~120s 随机重发；点击后验证位移/船速，失败重试/降级 | 离线实现完成，待实机验证（ISS-001） |
| 随机开火/消耗品 | 攻击计时器随机点击开火，按比例（默认 15%）使用消耗品 | 离线实现完成，待实机验证 |
| 死亡/结算处理 | 仅当血条**确认归零**（颜色无关的填充比例证据 + 连续帧 + TTL）才提前退出；无法确认时等待自然结算 | 离线实现完成，待实机回归（ISS-002） |
| 安全机制 | **F12 紧急停止**、**F11 暂停/恢复**、窗口失焦暂停、主循环心跳看门狗；F12/心跳在监控线程直接关闭输入门禁并请求释放 | 实机已验证基础上强化（ISS-004/005/006/009） |
| 多账号 | 本机 `accounts.yaml` 保存**别名与独立配置**（每日上限/允许时段等），不保存账号密码；会话间手动切号/轮换 | 离线实现完成 |
| 按船名动态选船 | 启动传 `--ship-name 铁公爵`，脚本在港口底部船只轮播条滚动查找、点击，并用 `selected.png` / `selected_name.png` 确认已选中后才开局 | 实机已验证基础上修复（ISS-007） |
| 每场开局校验 | 只确认已选中目标船；**不校验信号旗/经济加成卡**（2026-10-31 用户确认取消）；装备界面不读不点 | 离线实现完成（ISS-007 + 2026-10-31 口径） |
| 单实例与清理 | Windows 命名互斥量 + data 锁文件；重复启动退出码 3；会话异常也执行统一清理 | 离线实现完成（ISS-003/008） |
| 运行记录 | SQLite 记录会话/战斗、文本日志、按场清理临时截图；事件关联当前场次编号 | 离线实现完成（ISS-010） |
| 标定/环境工具 | `validate`、`check_env`、`calibrate_*`、`capture_marker`、`record`、`replay`、`stats` | 已完成，部分实机项待回填 |
| GUI（设计） | 运行页/日志页/标定与设置页、运行服务抽取、船名输入与船卡导入、账号轮换等待态 | 设计稿完成，未实施 |

### 明确不做的事

- 不识别地图、不标航线（当前默认 `navigation.mode: autopilot`，只有旧 waypoints 模式需要地图包）；
- 不读取/修改装备与配件，不点「出售/拆解/兑换/商店」类按钮，不售卖任何船只或装备；
- 不保存账号、密码、令牌，不做自动登录；
- 不使用 OCR，因此**每艘新船首次使用需要截一次该船的港口卡片模板**，并为 ISS-007 的
  「已选中确认」标定 `selected.png`（选中态卡片，含选中高亮/边框）与 `selected_name.png`
  （右侧详情面板指挥官上方的船名文字，更稳的兜底证据；见 6.1 节）。

## 3. 架构与模块

```text
src/
├── common/        公共类型（Action/Observation/State…）、坐标变换、时钟、Win32 窗口/DPI
├── config/        config.yaml/profile.yaml/keys.yaml/ship.yaml/maps/accounts 加载与校验
├── perception/    GDI+PrintWindow 截屏、模板匹配、ORB 地图识别、舰船定位、死亡判定、感知引擎
├── behavior/      随机计时器与行为调度
├── execution/     SendInput 输入线程、动作队列、安全热键/看门狗
├── navigation/    autopilot（默认）与旧 waypoints 航线导航
├── state_machine/ 状态机、步骤序列执行器、会话控制、船只校验、账号轮换
├── storage/       SQLite、文本日志、截图管理
├── tools/         validate/check_env/calibrate_*/capture_marker/record/replay/stats
└── main.py        命令行入口、运行时装配、账号轮换、主循环
```

关键设计点：

1. **截屏**：GDI BitBlt 优先；战舰世界窗口 BitBlt 恒黑屏时自动切换 **PrintWindow(PW_RENDERFULLCONTENT)**
   并记住该模式（约 70ms/帧，2fps 足够），不再每帧重试黑屏。
2. **识别**：归一化区域 + 多尺度模板匹配；`Observation.features` 除当前状态特征外，
   还包含**所有步骤序列/退出配置引用的特征**（避免 `wait_feature` 永远等不到装备页等跨状态特征）。
3. **状态机**：INIT / PORT / START_COOP / QUEUEING / LOADING / BATTLE_ACTIVE / BATTLE_FINISHED /
   DEAD_PENDING_EXIT / EXIT_MENU_OPEN / EXIT_CONFIRMING / EXITING / POST_EXIT_INTERFACE /
   ERROR_RECOVERY / PAUSED / STOPPING，全部转移由观察到的界面特征驱动。
4. **每船独立模板**：`ships/<ship_id>/card.png` 用于在轮播条找船；`selected.png`（ISS-007）
   用于确认“目标船已选中”（选中态高亮卡片，不能把“卡片可见”当作已选中）；`selected_name.png`
   （2026-10-31 实机补充）是右侧详情面板指挥官上方的当前选中船名，与卡片背景无关、跨帧更稳，
   与 `selected.png` 任一命中即确认；可选 `hp_bar.png`（血条面板上的「等级+舰名」字样）
   用于「血条消失」死亡信号，未提供时自动禁用该信号。
5. **安全边界**：游戏窗口必须前台（否则暂停）；F12 与心跳超时由独立看门狗线程检测，
   在监控线程内直接关闭输入门禁并请求输入线程释放所有按键/鼠标；暂停/恢复共用
   `StopController`，战斗内暂停恢复保留场次编号（ISS-004/005/006）。

## 6. 快速开始

> 本机 `python` 可能是应用商店占位符，统一用 `py -3.14`；仓库根目录提供了 `wows.cmd` / `wows-tool.cmd`。

```powershell
# 安装依赖
py -3.14 -m pip install -r requirements.txt
py -3.14 -m pip install pytest ruff

# 校验配置（应为 0 error）
.\wows-tool.cmd validate --root .

# 离线自检（不需要游戏）
py -3.14 -m pytest tests -q
py -3.14 -m ruff check src tests

# 单场试跑（游戏停在港口、联合作战模式；启动后不要动键鼠）
.\wows.cmd --ship-name 铁公爵 --max-battles 1 --log-level DEBUG
```

运行中：**F12 立即停止**、F11 暂停/恢复；窗口切走会暂停、回到游戏自动继续。
日志在 `logs/`，战斗数据在 `data/wows_script.db`。

### 换船 / 新增船

```powershell
# 1) 港口截图：目标船在底部轮播条完整可见（最好选中）
# 2) 标定船卡（GUI 框选：船体剪影+船名，避开等级/+50% 徽章与选中边框）
.\wows-tool.cmd calibrate_ship --root . --ship-id iron_duke --display-name 铁公爵 --screenshot "screenshots\港口截图.png"
# 3) 启动时输入船名
.\wows.cmd --ship-name 铁公爵
```

每艘新船首次使用需一次船卡标定；若想让该船启用「血条消失」死亡信号，再补一张该船战斗截图裁成
`ships/<id>/hp_bar.png` 并在 `ship.yaml` 写 `hp_bar_template: hp_bar.png`。

**限制**

- 模板对 UI 缩放/分辨率敏感（当前标定 2560×1600、100% 缩放）；换分辨率/改 UI 缩放需重新标定
  标签页等模板；
- 不使用 OCR：新船需要一次卡片标定 + 一次选中态卡片（`selected.png`）标定；
  船名输入依赖 `ships/*/ship.yaml` 的 `display_name`；
- 账号不做自动登录：需先手动登录目标账号，再启动脚本（`--account` 仅做本地档案/统计区分）；
- 排队就绪提示「进入战斗」暂无模板，当前等待游戏自动进入；
- 旧 waypoints 地图识别模式需要地图包（底图/出生点/航线），当前默认 autopilot 不需要；
- ISS-001/002/006/007 等修复的实机结论未回填前，不接受“已修复”的对外结论。

**计划**

1. 按 `docs/实机问题记录.md` 的修复验收标准做一轮实机回归（ISS-001/002/005/006/007 优先）；

5. 按 `design/GUI界面设计文档.md` 实施 M0（运行服务抽取）→ M1（运行页/日志页）→
   M2（船卡导入/标定入口）→ M3（账号轮换）；
