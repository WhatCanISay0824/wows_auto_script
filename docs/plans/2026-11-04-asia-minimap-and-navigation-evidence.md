# 亚服小地图与导航证据修复方案

## 问题与授权

用户已确认由 Codex 完成上一轮日志核查发现的两项问题。本轮直接在现有工作区实施，保留所有既有修改，不删除文件，不提交或推送，不操作真实游戏。使用 brainstorming、writing-plans 的设计与验收流程，由 Codex 完成设计、编码与验证。

会话 40、第 61 场使用 `wg_asia`。2560×1600 的诊断图中小地图外框约为 `[2040,1080,2560,1600)`，亚服配置却仍是 `[2184,1224,2560,1600)`。实际裁剪缺失左上区域，识别位置和全图归一化坐标都受影响。行为启动后约 110.8 秒才首次记录己方位置可用；记录了 7 次导航点选，前 6 次验证失败并排除了目标，第 7 次通过位移确认。

旧验证将缺失或丢失的己方位置直接跳过，超时后仍记录 0 位移、0 速度并排除目标；预测位置也能进入验证。这些观测不能证明目标不可用。旧测试大量复用时间为 0 的静态观测，不能作为验证窗口内的新鲜静止证据。

## 设计

选择局部标定与证据分流，不同步其他服务器，也不通过降低阈值或任意重试解决。

1. 亚服 `minimap.rect` 改为 `[0.796875,0.675,1,1]`，保留 2 像素边框，内容区为 516×516。己方标记颜色采用已有实图通过原模板分数门槛的 `[0,0,180]`～`[180,140,255]`，使文字覆盖下的白色标记仍能使用原始掩码回退。镜头扇区、敌舰颜色、模板匹配阈值、其他服务器和船只文件不变，保留 `calibration_required`。
2. 导航验证只接收关图后的不同帧时间、新鲜且有限的 marker 位置，置信度至少 0.6；predicted/lost 不构成位移或静止证据。沿用现有 2 秒画面缺失宽限作为新鲜度和连续观测间隔上限。预先的位移参考只有可靠 marker 可以提供。
3. 正向移动证据仍按原位移/速度阈值立即确认。否定移动需要至少两张不同时间的可靠截图，连续样本覆盖验证窗口的大部分时间：起始、结束及相邻样本间隔均不超过 2 秒。中途无效定位会中断静止证据，恢复后重新积累。不能用一张重复截图或一张超时前刚出现的位置排除目标。
4. 超时且证据不足时，记录 `autopilot_verify_waiting`，原因 `position_evidence_insufficient`，包含有效样本数和覆盖时间；保留当前目标、失败区域和重试计数，不按 M、不点击。开始新的同长度验证窗口，关图后的正常行为可继续。恢复可靠观测后，按实际移动确认或按充分静止证据进入原有选点重试。停止、死亡和显式替换目标继续沿用既有入口，不能被等待阻塞。
5. 真正的验证失败保留 `autopilot_verify_failed`、`autopilot_target_rejected` 和有界失败邻域，补充证据摘要，日志表述为“有效观测未确认移动”。不将未观测到的位置填为已测得的零值。

## 文件职责

- `profiles/wg_asia/profile.yaml`、`profiles/wg_asia/README.md`：本次亚服几何和标记标定及验证范围。
- `src/navigation/autopilot.py`：可靠观测、验证窗口、证据不足等待与已有失败分支。
- `tests/test_autopilot_evidence.py`：缺标记、预测、低置信度、过期/未来帧、重复帧、晚出现、间歇丢失、恢复移动/静止、显式替换和停止。
- `tests/test_autopilot.py`、`tests/test_autopilot_terrain.py`：静止失败测试改为窗口内真实新帧序列，保留正向移动、用户目标和输入顺序回归。
- `tests/test_combat_replay.py`：现有真实小地图按亚服正式配置走感知、己方坐标和调度回放；不将国服截图称为亚服实机样本。
- `CLAUDE.md`、本文：实际实现与验收记录。

## 实际验收

1. 修改前，新增证据与亚服几何回归为 15 项失败、1 项通过。缺失、预测、低置信度、非有限位置、过期/未来帧、重复帧和晚到位置都能复现旧实现错误进入目标失败；两份小地图样本均显示旧内容区只有 372×372。输出见 `pytest_work/asia_navigation_1104/red.txt`。
2. 相关 78 项通过，见 `pytest_work/asia_navigation_1104/related.txt`。随后补充亚服配置的完整行为往返回放，3 项亚服回放通过，见 `asia-replay.txt`。验证使用正式感知、导航和调度，国服保存样本按亚服配置裁剪；自身坐标与全图归一化符合实际 516×516 内容区，没有将国服样本解释为亚服实机验收。
3. 第 61 场本地死亡截图离线读取：旧内容区为 `[2186,1226,372,372]`，修正后为 `[2042,1082,516,516]`；两种裁剪都没有有效己方 marker，修正后没有把死亡画面的其他图案当成可用己方标记。结果见 `pytest_work/asia_navigation_1104/actual-death-replay.json`。这张死亡图仅验证几何与此负例，不能证明存活时的颜色和位置一定正确。
4. 新验证覆盖完全缺帧、窗口缺失、截屏错误、预测/丢失位置、间歇丢失、重复/过期/未来帧、迟到样本、恢复移动、恢复静止，以及显式替换与停止。等待分支不生成新的开图或点击动作；获得关图后的新画面即可释放行为隔离。移动确认仍可用原位移阈值或有效速度，HUD 提示不能单独确认。失去位置后清理旧位移参考，避免恢复时将预测偏差当成移动。
5. 全套 `py -3.14 -m pytest tests -o addopts='' -q --tb=short -r s` 为 1366 项通过、1 项缺少本地血条样本跳过，耗时 79.72 秒，见 `pytest_work/asia_navigation_1104/full.txt`。Ruff 通过；以列宁格勒校验四套配置均零错误，国服 4 条已有提示，直营服各 5 条已有提示，见同目录 `ruff.txt`、`validation.json`。`git diff --check` 通过。
6. 本轮运行代码只修改导航验证，配置只修改亚服的小地图几何、己方标记颜色与说明。其他服务器、镜头颜色、船只、死亡授权和前次决策时间修复均保留，没有暂存、提交、推送或操作真实游戏。重启后应优先检查日志不再长时间缺己方位置，证据不足时出现 `autopilot_verify_waiting`，且该等待期间没有重复 M 开图。
