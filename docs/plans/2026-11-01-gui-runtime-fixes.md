# 2026-11-01 界面与战斗运行修复方案

## 背景与证据

用户实测发现文字过小、全屏留白过多、下拉控件偏离预览、战斗行为未执行、小地图空白。保留现有 Tk、运行服务、唯一输入线程和 YAML 配置，不更换框架。按用户授权由 Codex 设计并直接实施；只做必要回归检查，实际游戏效果由用户验证。

本次会话日志 `logs/session_20261101_104705.log` 对应会话 20、场次 8。10:48:13 行为调度器已启动；10:48:34 失焦暂停后，出现约 1100 次恢复与再暂停。日志没有实际 camera_move、fire 或 watchdog 事件。代码路径表明窗口自动恢复只打开输入门禁，没有清除共享控制器的暂停请求，下一轮运行循环会再次暂停并重建行为计时器。显式恢复后窗口缓存也可能仍为失焦，造成恢复后立即暂停。

地图发布当前受整个导航验证阶段阻塞；首次战斗观察后立即开图，可能还没有保存第一张地图。暂停时无条件清空地图，使用户切到工具查看时也丢失本场图像。

## 方案与边界

### 1. 字体与布局

`src/gui/widgets.py` 使用能跟随 Windows DPI 的字体和统一尺寸换算，次要文字不再固定为 12 物理像素。保留原预览的全高侧栏、单行控制栏、三项摘要、地图及详情、记录和性能栏。地图从固定 300 像素改为根据可用宽高扩展，记录区利用剩余高度；小窗口纵向滚动，停止按钮固定可见。设置表单保持两列并限制无意义拉伸。

### 2. 控件精简

`src/gui/run_page.py` 客户端只有一个时显示只读文本，账号没有其他选项时显示默认账号；账号选项不超过四个时使用直接点选的单选项，更多选项才使用下拉框。船名输入和已登记船列表合并为一个可输入的选择框，候选同时列出船名与档案编号，继续支持匹配、同名档案选择和首次导入。日志级别保留一个必要的下拉框。配置编辑、运行中只读和后台校验规则保留。

### 3. 暂停恢复与行为运行

`src/execution/safety.py` 与 `src/state_machine/machine.py` 对窗口原因的自动恢复同步清除对应暂停请求，不能清除后来的手动暂停或停止。`src/runtime/runner.py` 显式恢复成功后立即刷新窗口信息，避免缓存失焦造成再次暂停。新回归检查使用真实状态机、共享控制器及行为调度器，连续推进到实际动作生成，并覆盖暂停恢复后的继续执行。

导航打开、点击和关闭地图时继续隔离战斗行为。`src/navigation/autopilot.py` 在关图后取得新鲜战斗画面后释放隔离，不让整个移动验证窗口阻塞正常行为。恢复不重复施加开局安静时间，不重置本场消耗品用量。

### 4. 小地图

`src/runtime/runner.py` 在生成开图动作前保存当前战斗帧的小地图；仅在地图界面或关图后尚无新帧时停止更新。暂停和 GUI 等待期间保留同场最近地图及原始时间，不伪造实时画面；结束场次或进入另一场时清除。`src/runtime/messages.py`、`service.py` 和数据页传递真实不可用原因，避免只显示空白。继续使用现有截图内容区，不引入额外截屏线程。

## 实施结果与证据范围

相关测试 218 项通过，ruff 通过。新回归覆盖失焦后连续运行、立即恢复时刷新窗口缓存、行为首次启动前暂停后的初始化、恢复后实际生成视角与开火动作、消耗品计数保留、地图暂停保留与跨场清理、关图新帧释放隔离，以及真实感知裁剪方法经运行服务快照传到 Tk 图像的路径。感知与输入仍使用离线数据或替身，未向游戏发送测试输入。

1280×820、1024×720 和实际 2560×1600 全屏窗口已截图复核，地图分别为 450、368、775 像素的方形区域，停止按钮均在窗口内。小窗口通过纵向滚动查看地图详情和记录。设置表单最大宽度为 1000 个逻辑像素，避免输入框横向拉满全屏。

截图位于 `screenshots/gui/data-fullscreen.png`、`settings-fullscreen.png`、`data-1280x820.png` 和 `data-1024x720.png`。图中地图来自历史游戏截图，经过现有感知裁剪方法；性能与运行状态使用演示值，不能作为本次游戏联调成功的证据。

实机优先检查三件事：进入新战斗后等待开局安静时间和正常行为间隔，观察日志是否出现 `camera_move`、`fire_burst` 或 `consumable`；暂停并恢复后确认动作继续且不反复暂停；切到工具查看小地图，再返回游戏确认画面更新时间继续变化。同场地图可直接点击提交目标，执行前复核新战斗帧；GUI 遮挡游戏时保留最近画面及原时间。
