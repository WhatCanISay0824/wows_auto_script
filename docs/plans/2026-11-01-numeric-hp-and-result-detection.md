# 数字零血、结算按钮与暂停恢复修复方案

## 背景与证据

本轮日志为 `logs/session_20261101_183758.log`，启动目标明确为 10 场，全局安全上限为 20 场。19:29:26 正常进入结算，但“继续战斗”与“回到港口”按钮未匹配。状态机每等待 20 秒便进入恢复，恢复又进入相同结算页，19:30:27 达到十分钟三次恢复的限制而暂停。19:57 用户停止，日志记录完成 4 场。这与上轮退出阶段没有处理结算的问题不同。

本次截图明确存在两个结算按钮。原完整按钮模板分别只有约 0.261、0.567 的分数；从原模板裁出文字后，在同一截图中分别达到约 0.926、1.000。因此先减少模板的背景和边缘，而非降低识别阈值。

死亡授权目前来自血条填充列比例。旧截图 `20261101_175015_death.png` 数字显示 734/41 200，不能视为零血；新图 `20261101_185249_death.png` 显示 0/41 200。用户要求以数字零血为准，血条填充不能继续单独授权退出。新零血图中截取的“0/”局部模板在零血图上为 1.000，在 734 残血图上约为 0.790。仍须排除 10/、100/ 等末尾含零的数字。

日志还证明：19:04 暂停后恢复到港口，数据库记录已中断，但会话计时仍认为上一场进行中，导致下一场 begin_battle 抛出“上一场战斗尚未结束”，出现 battle=None 的托管动作。需要同步清理计时状态，且中断场次不计入已完成目标。

## 设计与边界

保留截图和 OpenCV 模板技术，不新增通用 OCR、依赖、客户端访问方式或键鼠路径，不降低死亡证据和全局模板阈值。保留上一轮未提交修改。

1. 结算模板裁出完整文字与少量内边距，去掉按钮外框和大面积背景。已有定位区域、阈值、多尺度匹配和点击流程不变。其他确认、离开战斗、离开队列、加入战斗按钮同样裁出文字，精确范围见下表。船卡选中边框、港口当前标签、舰船标记等以边框或颜色为语义的模板保留必要信息，不改造通用匹配器。
2. 国服配置增加可选 `battle_hud.hp_zero_feature`，指向局部“0/”模板。数字专用匹配先消除背景：把 HSV 中红橙色（H≤28 或 H≥165，S≥130、V≥140）赋值 255，中性亮色（S<85、V>145）赋值 128，其余置零。模板与数字区域统一处理，再按配置尺度匹配，阈值 0.92，不更改通用模板匹配器。该处理在铁公爵零血图上为 1.000、列宁格勒零血图上约为 0.973，734 残血与满血样本均低于 0.690；原始灰度模板在列宁格勒零血图上仅约 0.723，不能直接用其命中结果作为必要条件。当前己方船名特征命中、零值模板命中、数字区域内红橙色当前血量字形只有这个零字形时，给出 `hp_current=0` 证据。若 10、100、1000、10000 等额外数字出现在零左侧，不授权；缺少分隔符、己方身份、零模板或有效帧均不授权。血条仍可提供存活和调试信息，但配置数字判零后，空条不能单独给出 zero。未配置数字特征的旧测试配置保留原兼容行为。
3. `DeathSignals` 增加 `hp_current: int | None = None`，目前只确认零值，不冒称读取任意血量。`DeathDetector.update` 增加同名可选关键字参数；有数值 0 的证据时不要求填充比例必须可用，不伪造填充比例。连续新帧、过期撤销、未知/存活撤销、观战排除和开局静默保持生效。死亡授权优先于导航和行为；日志输出数字判读及证据状态，便于用户复测。进入死亡等待时若本场已经确认数字零血，后续数字短暂不可见不能重新启动巡航；保留死亡等待并停止行为，直到取得新鲜零血授权后退出，或进入自然结算。这个本场标记不能代替发送退出动作前的新鲜授权，旧兼容场景的撤销规则不变。
4. 结算中维持 20 秒等待继续按钮、之后允许回港兜底的顺序。若结算证据仍存在但按钮暂未出现，留在结算状态等待最多 60 秒；不消耗通用恢复次数、不重置倒计时。60 秒仍无按钮时以明确原因暂停一次。若有继续按钮，60 秒内任何时刻均可继续。未知画面与其他恢复仍保留原次数限制，人工暂停、停止和场次上限优先。
5. `SessionController.abort_battle(reason)` 幂等关闭进行中的计时，记录中断原因与时长，不累计完成数。状态机中断当前上下文时同步调用。正常 end_battle 计数不变，返回港口后的新场能够创建有效记录。

## 执行与审核

初始执行通过 MixAgents Broker 的 `deepseek-flash` 路由派发，provider 为 `deepseek`，model 为 `deepseek-flash`。两个任务在部分产物落盘后均因接口返回 HTTP 402 Insufficient Balance 失败。向用户说明后，用户明确授权“由 Codex 直接完成”，后续实现、修正与审核由 Codex 完成，未切换其他外部 provider。

回归首先证明两处旧实现失败：结算缺按钮在第 20 秒进入 ERROR_RECOVERY；暂停恢复港口后真实 SessionController 仍有进行中的计时。审核同时纠正了部分未完成测试的假设：暂停应保留场次上下文；测试替身的步骤点击不是生产按钮动作；测试样本不能依赖未跟踪的 pytest_work。新数字测试读取正式资源 hp_zero_value.png。

已增加两项保护：通用结算超时不能抢先截断独立按钮等待；本场已经确认数字零血后，死亡等待超过原通用等待期限或暂停恢复也不能重启巡航。退出前的新鲜证据要求保持不变。
