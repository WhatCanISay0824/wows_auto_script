# 小地图输入与运行日志修复方案

## 背景和证据

用户要求直接点击 GUI 小地图获取目标，随后由脚本按 M 打开游戏自动驾驶地图、映射点击并关图。用户不需要提前按 M。沿用现有 Python、Tk、运行服务和唯一输入线程，不新增输入后端或依赖。

最新日志为 `logs/session_20261101_115848.log`。12:06:47 点击继续战斗，12:07:43 已创建第二场记录，因此连续战斗已进入下一场。12:13:03 的回港等待为 7.71 秒，失焦恢复后剩余 0.33 秒，符合不重置倒计时的规则。

日志中多次发生 `window_lost` 和 `window_unfocused` 暂停，没有用户目标接收或替换记录。当前 GUI、服务、运行线程均拒绝暂停状态下的地图目标，即使暂停原因只是切换窗口。窗口切换可能先经过其他前台窗口，现有判断立即暂停，随后切到本工具也无法选点。日志不足以确定每次失焦的前台进程，需补充有限的状态日志，不能宣称所有失焦都是误判。

12:12:20 与 12:12:42 恢复到死亡等待后，退出证据不足立即返回战斗并重启巡航。静态调用路径表明这会重置感知层的死亡证据。死亡提示不是退出授权，但也不能被当成存活证据。

12:00:34 的诊断截图显示“无效路径”和静止船速。当前截图的小地图网格约位于客户区右下角 `(2184, 1224)` 起的 376 像素正方形，配置却按约 512 像素裁剪，包含了网格左上方的战斗画面。错误裁剪影响 GUI 坐标与出生点归一化，需按现有 2560×1600 游戏画面校正。用户追加要求自动目标避开岛屿。本轮选择从当前小地图筛选水面终点，仍由游戏规划完整航线，不新增绕岛算法，也不把点击等同于移动成功。

## 方案和边界

1. 窗口失焦立即关闭输入门禁、清空旧动作并释放键鼠。使用 0.5 秒的前台稳定等待，每轮复查游戏和本工具。切到本工具进入 GUI 等待；持续切到其他应用仍进入原有暂停。捕获失败同样先复核前台，不能在已经切到本工具时直接推进状态机。手动暂停、停止、输入失败、紧急停止保持优先。
2. GUI 和服务在具有同场地图、自动驾驶模式时，允许因 `window_lost`、`window_unfocused`、`window_unavailable` 暂停的用户显式点击提交目标。运行线程再次核对当前暂停原因、共享控制器、场次、图像和窗口；手动暂停、异常暂停、停止、跨场一律拒绝。提交后只尝试切回游戏一次，失败时等待用户返回，不循环抢焦点。恢复仅清除已核对的窗口暂停请求，避免清除新的人工暂停。
3. 目标在状态机恢复后，以提交后的新战斗帧复核。必须先接受归一化坐标，再通过现有导航器产生 M 开图、映射点击、M 关图。不得要求用户预先开图，不向游戏小地图直接补发点击。
4. GUI 点选失败显示具体原因，反馈不被下一次空快照立即抹掉。记录点击、命令入队、运行线程接收或拒绝、等待新帧、目标应用或取消；日志包含场次、帧号、坐标和原因，不记录屏幕中玩家名称或凭据。等待日志只在状态变化时写入，禁止逐帧刷屏。
5. 死亡等待期间结算优先。当前血条证据为存活时允许返回战斗；退出授权暂时不足但死亡提示仍存在时保留等待，持续观察新帧，禁止重启巡航。现有超时和血条归零授权规则继续生效，不凭死亡提示发送退出输入。
6. 将 `profiles/cn360/profile.yaml` 小地图矩形校正为 `[0.853125, 0.765, 1.0, 1.0]`，保留 2 像素边框。该标定对应当前游戏的小地图大小；用户在游戏内调整小地图尺寸后仍需重新标定。
7. 新增水面目标筛选纯函数：仅从新鲜小地图中识别当前客户端的蓝色水面，排除陆地、图标与未知像素，保留至少地图短边 3.5% 的离岸距离；在默认目标附近 0.25 的归一化半径内选择最近安全点，优先使用与当前船位相连的水域，船位不可用时使用占比足够的主要水域。图像缺失、过旧或无可靠候选时暂缓默认巡航并记录原因，不盲点地图中心。已失败候选在后续无移动重试中排除邻近范围，成功移动或新场次清除。GUI 明确指定的单目标保持原坐标，不静默改成另一个目标。
8. 水面选择使用开图前的当前战斗帧，目标在本次 M 开图、点击、关图期间固定，不能拿全屏地图下的右下角画面重新判读。生产运行向导航器注入图像提供接口，验证帧号、窗口和截屏时间；不新增截屏循环。

## 文件职责

- `src/runtime/runner.py`：前台切换稳定等待、目标上下文复核、窗口暂停恢复、目标处理日志。
- `src/runtime/service.py`：允许窗口暂停下的明确选点请求，记录命令及拒绝反馈。
- `src/gui/data_page.py`：窗口暂停时同场选点、拒绝原因和持续反馈，布局不变。
- `src/state_machine/machine.py`：死亡等待不因证据暂缺重启巡航。
- `src/navigation/water_target.py`：当前客户端小地图的水面候选筛选，不发送输入。
- `src/navigation/autopilot.py`：开图前选择并固定自动目标，未移动时更换失败候选。
- `profiles/cn360/profile.yaml`：按当前游戏截图校正小地图区域。
- `tests/test_gui_cooperation.py`、`tests/test_gui_data.py`、`tests/test_gui_smoke.py`、`tests/test_runtime_service.py`、`tests/test_state_machine.py`：覆盖实际跨层调用流程及相关失败分支。
- `tests/test_water_target.py`、`tests/test_autopilot_terrain.py`：覆盖水面、陆地、海岸距离、失败候选轮换、图像不可用及用户目标保留。

## 验收结果

控制器独立运行上述九个测试文件，231 项全部通过，用时 17.55 秒，无跳过。代码检查通过，配置校验为 0 个错误、5 个警告。警告涉及尚未配置加载页和回港后界面特征、铁公爵空装备槽校验、自动驾驶模式未配置地图包，以及命令行船只覆盖默认配置。

集成审核中修正了生产地图回调的矩形比较：截图的窗口矩形为 `Rect`，需用 `to_tuple()` 与观察结果比较。新增真实 `Frame`、`Rect` 对象的回调检查，验证有效图像可以返回，错帧、旧帧、窗口不一致时拒绝。窗口短暂失焦时，如果 M 地图已打开，会先完成关图并等待新帧，再恢复导航，避免下一次 M 把开关顺序反转。

第一张诊断截图经生产小地图内容裁剪后为 372×372 像素，当前船位约为 `(0.9341, 0.4368)`；默认目标 `(0.5, 0.5632)` 被移至邻近安全水面 `(0.5108, 0.6075)`。这是已有截图的离线回放结果，不代表游戏已接受该目标。

用户实测时优先检查：切到 GUI 点选后脚本是否自动按 M 完成选点；自动目标是否避开岛屿并产生实际移动；提前死亡后是否回港重开，以及正常结算后是否继续战斗。若游戏内调整小地图大小，应重新标定裁剪矩形；不同地图的海面颜色和全屏地图投影误差仍需实测。

离线检查只证明实际覆盖的调用和输入生成，游戏内坐标精度、无效路径反馈及真实窗口切换由用户实测。推送已由用户明确授权，不改全局 Git 配置，不强推，不删除现有文件或历史。
