# GUI 数据页与自动巡航修复实施方案

## 背景与目标

当前运行服务、四页 Tk 界面、船只导入和性能采样已经接线，基线 1020 项测试通过。默认页仍以配置和状态列表为主，与已确认的预览有明显差距；数据记录和小地图尚未接入。最近一次会话发出了地图选点，但零位移、零船速时仅凭 HUD 模板就确认成功，后续截图显示舰船停在原地。

沿用 Python、Tk/ttk、现有感知线程和唯一输入执行器。继续扩充现有界面比换用网页框架成本低，也能保留已验证的启动、停止、船卡导入和清理逻辑。仅改颜色无法补齐数据功能，因此采用布局与数据通道一起完成的方案。

## 约束

- 保留当前未提交修改，不改变数据库结构，不引入全局依赖。
- 使用平面中性色、细线和留白，保留数据、性能、日志、设置四个入口。
- 性能保护沿用当前配置，默认 monitor，不自动启用停止阈值。
- GUI 不直接控制游戏输入。地图仅替换本场一个目标；下一场恢复默认。
- 工具前台时保持托管会话，暂缓游戏输入；其他应用失焦沿用暂停规则。
- 地图只复用已有截图，不额外启动截屏循环，不把旧图当作实时画面。
- 按用户授权，方案完成后由 Codex 在当前会话直接实施，无额外确认。

## 文件职责与实施顺序

1. `src/navigation/autopilot.py`：分开激活证据与移动证据；验证使用关图后的新观察；全屏地图失败后保留全屏路径限频重试；新增本场单目标覆盖接口，暂停恢复保留，场次结束清除。`tests/test_autopilot.py` 覆盖静止提示、重试、目标覆盖和恢复。
2. `src/runtime/messages.py`、`runner.py`、`service.py`：增加不可变地图帧和目标命令；运行线程裁剪、编码并发布最新帧；目标绑定场次、帧和有效期限，执行前再次校验。导航反馈读取真实确认状态。工具前台等待复用输入门禁，不运行游戏动作，返回后重新识别。停止、F12 和过载监测继续有效。
3. `src/runtime/history.py`：只读 SQLite 查询最近场次和今日统计，后台执行、有界结果；不存在数据库时返回空记录，查询失败明确显示原因。只展示真实采集的结束类型，不虚构胜负、收益或历史船名。
4. `src/gui/data_page.py`：数据摘要、按比例显示的地图、单目标点击和场次记录；同场地图可点击，无图、暂停、停止或非本场时禁用；显示真实帧龄及命令接收与执行反馈。
5. `src/gui/app.py`、`widgets.py`、`run_page.py`、`tools_page.py`：采用预览布局，默认数据页；设置中承载既有启动配置，保留原有接口与测试；压缩右侧摘要、最近日志，隐藏侧栏时回收宽度。保留停止与异常反馈。
6. 更新设计与项目进度文档，标明离线验证和实机验证的边界。

## 验收

- `py -3.14 -m pytest --disable-warnings --maxfail=3`：现有功能和新增行为通过。
- `py -3.14 -m ruff check src tests`，项目配置校验和 dry-run 无新增失败。
- 真实 Tk 窗口检查 1280×820 与 1024×720：地图、启动停止与导航不被挤掉；设置和日志可以滚动访问。
- 导航测试证明静止 HUD 提示不能冒充实际移动，验证失败不再进入已知无效的小地图路径。
- 地图命令测试覆盖同场旧帧提交、新战斗帧复核、跨场次、停止后提交、坐标边界和单目标替换；目标执行只走运行线程。
- 截图回放与模拟输入只证明离线路径；未完成真实游戏开局验证前，交付说明保留该证据缺口。


## 实施结果与实机交接

已完成四页浅色界面复原、SQLite 后台只读查询、闲置与运行中性能展示、真实 CPU 趋势、最新小地图、本场单目标替换、GUI 前台输入等待和输入发送前焦点复核。保留现有框架和保护模式，不更改数据库结构。

数据页使用贯穿全高的窄侧栏、单行运行栏、三项摘要、300 × 300 地图及右侧目标详情、场次记录和性能侧栏。小窗口通过纵向滚动访问记录，停止按钮固定可见；设置为两列表单，诊断信息可展开。深色外观尚未接入，按钮边角按 Tk 原生绘制。

巡航根因证据：最近一次会话在零位移、零船速时仅凭 HUD 模板确认成功。实机静止样本的灰度匹配分数约 0.7883，高于原阈值 0.72。已提高该模板阈值到 0.85，并将 HUD 激活与移动证据分开。关图后的新帧才能参与移动验证，开图前位置作为参考；恢复和新场次清除旧移动参考。验证失败保留全屏地图限频重试，不再转入已知无效的小地图直点路径。

已完成的检查：1054 项测试通过；ruff 通过；配置校验 0 错误、4 条既有警告；命令行 dry-run 退出码 0。真实 Tk 窗口检查 1280 × 820 与 1024 × 720，地图保持正方形，停止按钮可见，选点命令和过期禁用已检查。检查没有向游戏发送实际输入。按用户要求，后续检查交由用户实机完成，不继续扩大离线检查范围。

启动界面：在项目目录执行 `py -3.14 -m src.gui.main`。

实机重点：
1. 从港口启动并进入新战斗，确认 M 开图、点选、关图后舰船实际移动；若开局未生效，观察是否继续全屏地图重试。
2. 切到工具查看数据，确认会话和场次不重建；新鲜地图上更改一个目标，确认只尝试切回游戏一次并完成重设。下一场应恢复默认目标。
3. 验证暂停、停止和 F12 能释放键鼠；手动暂停或停止后，切回游戏不能被 GUI 等待逻辑覆盖。

当前限制：GUI 前台时保留最近地图，不持续发布可能被遮挡的游戏截图；同场地图可提交目标，执行前必须取得新战斗帧并复核。全屏地图仍按已有矩形标定换算，透视误差和实际航线效果待实机确认。“已检测到移动”只表示移动证据，不表示目标路线已被游戏确认。过载默认只监测，不自动启用停止阈值。
