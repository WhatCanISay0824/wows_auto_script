# 根据敌方标记交战与场间等待方案

## 背景和成功标准

用户收到挂机警告、收益限制，提示需完成一场解除。尚无官方提示整屏样本，不能从脚本日志确定系统使用的具体判定规则；本轮改善实际交战行为，不承诺避免检测或自动解除限制。

现有代码问题明确：PORT 将配置的随机场间等待钳位到 3～10 秒，结算继续战斗绕过等待；行为调度只按 25～120 秒的计时随机开火，视角动作与目标无关。调度器的 heading 是相对鼠标运动方向，不能当作游戏中的镜头朝向。

成功标准：两条开局路径都使用每场一次的随机等待；新鲜且连续确认的敌方实心标记才可触发交战；镜头方向来自小地图扇区而非舰船航向；转向后必须取得新帧再开火；有目标时不运行大幅随机视角；无目标或证据过期立即停止交战输入。离线回放和模拟测试分别说明覆盖范围，不冒充实机结果。

## 选择与取舍

只加大随机等待不能解决不参与交战；继续盲目转向和随机开火也不能证明朝向敌人。因此采用配置化场间等待、颜色和形状识别、小步反馈转向三部分。不引入 OCR、网络识别、游戏内存访问或新依赖。

小地图红色/橙色像素并不都代表可见敌舰：占领点、文字、空心历史标记需要排除；粉色标记不当作敌舰。通过实心连通域面积、形状、填充率及厚度筛选候选，连续两个不同截图才确认。重叠、边缘裁切、空心或不确定标记宁可不接纳。该方法可能漏掉拥挤或特殊符号，需用真实样本记录局限。

镜头方向由小地图半透明青色扇区的径向颜色分布估计。颜色范围放入客户端 minimap 配置。缺少可靠己方白色标记、扇区证据或新鲜帧时不进行定向输入。舰船航向不替代镜头朝向。

## 组件和接口

- `src/common/types.py`：增加 EnemyContact、CombatObservation 和 Observation.combat，携带己方位置、镜头方向、敌方位置、确认帧及时间；增加原地单次按键动作，使开火遵守 keys.yaml 且不会移动指针改变镜头。按下与释放由后端一个动作完成，不能因限流截掉释放。
- `src/perception/combat.py`：纯图像候选筛选、扇区估计及连续帧确认；只读取配置 minimap 内容区，不操作键鼠。每次新帧计算一次，同帧重复 observe 不重复确认。
- `src/perception/engine.py`：在启用定向交战且 BATTLE_ACTIVE 时生成 combat 观察；其他界面不产生交战证据。新战斗清空确认历史。
- `src/behavior/combat.py`：保持目标、最短角差、有限步长水平转向和开火尝试调度。输入为 CombatObservation、当前时间及行为配置；输出普通 Action 列表及日志。每次转向后等待更新且晚于动作时间的画面。开火尝试间隔 3～5 秒；不是读取装填状态，不保证命中。
- `src/behavior/scheduler.py`：新增 targeted_combat 模式。该模式停用随机视角、随机开火、随机消耗品和活动看门狗，防止旧逻辑打断瞄准。现有 `keys.yaml` 的消耗品栏位为 1～5 且仍待实机确认，停止随机按这些键，避免切换武器干扰交战。已有每分钟输入额度仍统一生效；单次原地点击不可拆断。
- `src/config/models.py`、`loader.py`、`validate.py`：解析和检查交战参数、客户端颜色范围。模型默认关闭，兼容未标定的旧配置；项目 config.yaml 显式启用。颜色和输入增益允许按实际客户端调整。
- `src/state_machine/machine.py`：移除 PORT 的固定钳位；结算继续战斗等待同一随机范围，保留同场期限，等待期间每步检查停止要求；等待不消耗按钮识别的 60 秒超时。继续战斗按钮等待期和场间等待期区分，最终使用当前帧按钮位置，不缓存旧点击坐标。
- `config.yaml`：session.between_battle_s=[25,75]；behavior 启用 targeted_combat，设置开火间隔、对齐角阈值、小步转向上限、镜头增益和反馈间隔。四套 profile 标记颜色采用简体中文现有基线，仍保留直营服待标定要求。

## 范围与边界

本轮由 Codex 直接实施；保留工作区已有退出修复和模板审计成果，不修改用户新增船包，不提交或推送。无可靠图像证据时保持镜头稳定；可靠且无敌舰候选时的平滑视角动作按 `docs/plans/2026-11-03-idle-camera.md` 执行。有目标交战不增加随机晃动。没有可靠的装填读数，不增加“装填已结束”的假判定。定向只解决大致水平朝向，不做距离弹道、垂直瞄准、命中保证或视线无遮挡判断；小地图已显示目标也不等于能直接命中。
