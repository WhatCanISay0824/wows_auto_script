# wows_auto_script

《战舰世界》联合作战（PvE）模式的本地托管脚本。程序通过截屏识别界面，再用模拟键鼠操作游戏，提供 GUI 与 CLI 两个入口；不读取游戏内存，不修改客户端文件，不抓取网络数据，也不使用 OCR。

一局的正常流程是：港口选船并确认已选中 -> 加入战斗 -> 脚本按 M 打开全屏地图并点选目标 -> 无目标时小幅移动视角，有可靠敌舰证据时转向并尝试开火 -> 死亡后确认并回港，或正常结算后继续 -> 场间等待后进入下一场。脚本不校验信号旗或经济加成卡。

> 风险提示：自动化脚本违反游戏官方第三方软件政策，处罚对象是账号。本项目仅用于本地自动化技术研究，请使用可弃小号、限制场次与时长、不要公开传播。调整输入节奏不能保证规避系统识别，后果由使用者自行承担。

## 当前状态

截至 2026-11-11，用户多次实测反馈核心托管流程较稳定。11 月 5、6、8、10、11 日的五次完整会话分别完成 3、3、3、4、5 场，共 18 场，均在达到配置上限后停止。这些会话日志未出现 ERROR、CRITICAL 或未来帧误判 `future_frame` 记录。

当前版本包含退出确认按钮修正、死亡退出与结算交接、定向交战、无目标视角移动、截屏后决策时间刷新，以及亚服小地图和导航证据修复。11 月 11 日的会话完成 5 场，日志记录 139 次无目标视角动作、92 次定向转向和 191 次开火尝试，最后正常回港并停止。动作日志证明调度流程已运行，不代表实际命中、收益或游戏系统的挂机判定。

GUI 手动改点、各类暂停恢复、批量账号轮换和过载自动保护等路径，仍按各自验收范围判断，不从连续托管结果推导全部通过。发布前检查结果见文末“检查与文档”。

## 快速开始

### 环境

- Windows 11。
- Python 3.14，安装时包含 Tk。
- 游戏以 2560×1600 无边框窗口运行，UI 缩放固定，小地图使用整图、北向显示。
- 游戏窗口在前台；系统不锁屏、不休眠。

所有命令都必须在仓库根目录执行。

### 安装依赖

```powershell
git clone https://github.com/WhatCanISay0824/wows_auto_script.git
cd wows_auto_script
py -3.14 -m pip install -r requirements.txt
```

运行依赖为 NumPy、OpenCV、PyYAML 和 Pillow。GUI 的图像导入与预览使用 Pillow。

### 检查配置

```powershell
py -3.14 -m src.tools.validate --ship iron_duke
```

`iron_duke` 是示例船只档案。换成其他船时，应先按“新船校准”准备对应模板。

### 启动 GUI

```powershell
py -3.14 -m src.gui.main
```

在设置页选择客户端、账号别名、船只、场次上限、日志级别和是否轮换，然后启动托管。不需要提前在游戏里按 M。

“客户端 / 服务器”提供以下配置，选择后船只列表、配置校验、船卡导入和标定工具均使用对应目录：

| 选项 | CLI 参数 | 模板情况 |
| --- | --- | --- |
| 国服 360 | `--profile cn360` | 已有国服实机模板 |
| 直营服 · 亚服 | `--profile wg_asia` | 已修正 520 像素小地图和己方标记范围，其余模板仍需按本服核对 |
| 直营服 · 欧服 | `--profile wg_eu` | 简体中文初始模板，待本服实机标定 |
| 直营服 · 美服 | `--profile wg_na` | 简体中文初始模板，待本服实机标定 |

请先在游戏启动器登录目标服务器；这里选择的是脚本使用的客户端配置，不会替游戏切区。直营服配置各自保存完整独立文件，最初来自国服简体中文 2560×1600 基线，校验会提示待标定。不同语言、布局或小地图大小需要从本服截图重新标定。具体步骤见对应目录的 README，例如 [亚服配置说明](profiles/wg_asia/README.md)。

托管时长上限目前不能在 GUI 中编辑；GUI 只读显示配置中的生效值。如需修改时长上限，停止运行后编辑 `config.yaml`，再重新启动。所有会影响运行行为的设置在运行中只读。

### 命令行入口

```powershell
.\wows.cmd --ship-name 铁公爵 --max-battles 1
.\wows.cmd --dry-run
```

等价完整命令为 `py -3.14 -m src.main ...`。`--dry-run` 只执行启动检查，不进入游戏控制。GUI 与 CLI 共用运行服务和单实例锁，停止一个实例并完成清理后，再启动另一个。

常用维护命令：

```powershell
.\wows-tool.cmd check_env --profile cn360
.\wows-tool.cmd calibrate_profile --profile cn360
.\wows-tool.cmd calibrate_map --map-dir maps/<map_id>
```

`calibrate_map` 用于 waypoints 模式的地图包；默认 autopilot 不要求地图包。

## GUI 模块

界面采用浅色桌面布局，顶部提供统一的启动、暂停/恢复和停止控制。四个模块共享同一份运行状态。

| 模块 | 主要内容 |
| --- | --- |
| 数据 | 本次托管摘要、最近场次记录、最近小地图与帧龄、当前场次单目标替换 |
| 性能 | 整机 CPU、物理内存、可用内存、脚本进程 CPU/内存、截图耗时和监测时间 |
| 日志 | 运行日志文本、级别/关键词/场次过滤、自动滚动 |
| 设置 | 客户端、账号别名、船只、场次上限、日志级别、轮换；船卡导入与标定入口；时长上限只读展示 |

已有功能不等于所有非核心路径都已实机验收。数据页可以显示真实数据库记录，但不会把 `finished` 推导成胜利，也不展示没有采集来源的伤害、经验或收益。

## 前台协作

- 切到本工具不会停止托管，只会停止需要游戏前台的动作。小地图保留最近一帧及帧龄，不在后台持续实时截图。
- 在数据页点击当前场次保留的小地图，可替换本场的单目标。提交后脚本只尝试切回游戏一次，并以新战斗帧复核；复核通过后自动按 M 开图、在映射位置点击、再按 M 关图。后续本场沿用该目标，新场次恢复默认目标。
- 因游戏窗口失焦或不可用而暂停时，可以显式点选并发起返回请求。人工暂停、异常暂停和停止不会被一次地图点击恢复。
- 切到其他应用造成的暂停，需要回到游戏并复核后恢复，也可以使用 F11 或 GUI 的恢复按钮。项目不承诺对其他应用进行后台游戏控制。
- F12 是紧急停止，立即关闭输入门禁并释放键鼠。GUI 与 CLI 共用同一把单实例锁。

## 自动巡航

默认目标位于我方出生点关于地图中心的对称区域附近，形式为 `(0.5, 1 - own_y)`。每次自动点选前，从当前新鲜小地图中筛选已知水面，排除陆地、图标和未知像素，并优先选择离岸且与当前位置同连通水域的候选。

- 船位缺失时，候选仍须通过水面验证。没有可靠图像或安全候选时，不盲点地图中心，约 10 秒后再试。
- 点选后，只有连续可靠的新截图证明未移动时，才避开失败邻域并换点。定位缺失、预测位置、低置信度、重复或过期截图只会保留目标等待，不反复开图，也不将目标记为失败。全屏地图路径快速重试后转为限频，不降级为直接点击小地图。
- HUD 只作辅助证据；只有新帧中的位移或船速证据才确认航向生效。
- 用户明确提交的目标保持原坐标，不静默改成另一个“更安全”的点。目标位于水面不代表整条航线一定可达。
- 自动巡航默认每 60–120 秒重新设置一次目标，避免到点后停船或卡住。

国服和亚服当前小地图标定为 `[0.796875, 0.675, 1, 1]`。在 2560×1600 下外框约 520×520，2 像素边框内的内容区为 516×516。国服以 11 月 3 日晚截图标定；亚服以 11 月 4 日截图修正范围，并保留各服独立的镜头扇区颜色配置。更换地图显示效果后需核对，单独扩大颜色范围可能把背景当作扇区。欧服和美服仍使用各自待标定配置。若在游戏内调整小地图大小，必须重新标定。

全屏地图按内容区外接矩形换算，现有透视梯形会留下约 2% 内容区高度的纵向残差，不承诺在 2560×1600 下逐像素精确。

## 战斗中的镜头和开火

项目配置默认启用 `behavior.targeted_combat`。连续两张新截图确认小地图上有实心敌舰标记，且己方位置和青色镜头扇区可识别时，脚本才进行定向交战。空心历史标记、占领点和粉色友舰不作为开火依据。

镜头只按目标的水平角差小步移动，每次最多 80 个鼠标计数，之后至少等待 0.6 秒和后续截图。镜头朝向误差在 12° 以内时，按 `keys.yaml` 的开火键原地单击，尝试间隔为 3～5 秒。旧的随机视角、随机点射和活动兜底晃动在此模式下停止，装填期间也不主动晃动。目标消失、镜头方向不明、画面过期、开图、死亡或结算时不继续交战输入。连续三次转向未改善角度误差时停止继续转动，并记录 `aim_not_responding`。

定向模式不随机按消耗品键。现有 `keys.yaml` 的消耗品栏位仍待实机确认，避免自动按这些键切换武器，干扰开火。

可靠画面中没有敌舰或候选标记时，使用独立的无目标视角动作：默认每隔 3～4.5 秒安排一次左右随机的小幅水平移动，总幅度 24～48 个鼠标计数，在约 0.5～0.7 秒内按缓入缓出的曲线分步完成，不改变垂直方向。起动时先发 1 个计数，随后各步最多 24 个计数；每次只生成当前一步，不排队执行整段运动。敌方候选标记一出现就取消剩余移动，继续沿用原有的有敌人交战逻辑。

无目标视角不受开局十秒交战静默期限制，仍遵守前台、弹窗、帧龄、开图、死亡和停止门禁。没有可靠小地图或己方位置时不会盲动；无目标水平移动不依赖镜头扇区方向。它单独限流，默认每分钟最多 180 个移动输入，不消耗交战的 40 次额度；输入队列积压或主循环中断时不补发大步。参数以 `behavior.idle_camera_` 开头，方案见 [无敌人期间的平滑视角动作](docs/plans/2026-11-03-idle-camera.md)。

日志中的 `behavior_mode` 记录行为模式和等待原因，用于区分无目标移动、候选确认、交战及证据或界面门禁阻止输入。模式与原因不变时不重复记录。排队或加载期间暂停后，恢复会保留本进程创建的场次并继续相应流程；尚未进入战斗不会提前启动行为。新进程仍不自动接管已经开始的战斗。

这只是根据小地图调整大致水平朝向并尝试开火，没有装填状态、射程、垂直瞄准或弹道计算。标记重叠、边缘裁切及特殊图标可能漏检。`aim_counts_per_degree` 需按游戏灵敏度实测；敌舰和扇区颜色范围在各客户端 `profile.yaml` 的 `minimap.enemy_hsv_*`、`minimap.view_cone_hsv_*` 中配置。直营服仍需使用本服截图标定。修改配置后重启脚本生效。

离线验收使用真实小地图回放和替身输入后端，覆盖识别、调度和输入衔接；近期实机日志也已记录转向与开火尝试。日志本身不能确认每次输入在游戏中的实际效果、命中或限制解除。方案和验收范围见 [交战与场间等待方案](docs/plans/2026-11-03-targeted-combat-and-pacing.md)。

## 性能保护

默认 `overload.mode: monitor`，只显示和记录监控结果，不自动暂停或停止托管。`pause_stop` 与 `stop` 是可选配置模式，自动暂停/停止效果需另行验收。

CPU 占用高本身不会直接触发保护。主要判定依据是提交内存余量不足和清醒调度持续迟到。具体阈值、采样窗口和滞回规则见 [GUI 过载保护阈值设计](design/GUI过载保护阈值设计.md)。

## 连战与上限

- 只有取得死亡证据授权时才提前退出。单独看到死亡提示不足以发送退出输入，脚本会继续等待可确认的状态。
- 已确认死亡的当前场次如果退出菜单超时，会停止退出输入并等待正常结算或回港，等待期限为 `timeouts.exit_s`（默认 180 秒）。到期仍无法识别时，以“死亡退出未成功，等待正常结算或回港超时”暂停；等待期间不恢复巡航和随机动作，不增加完成数。
- 场间等待使用 `session.between_battle_s`，项目配置为每场单独抽取 25～75 秒。提前退出回港和结算页继续战斗均使用该配置；同一场间只抽取一次，切换路径、暂停和恢复不会重置期限。首次开局不等待。
- 正常结算优先在等待到期后点击继续战斗，等待不消耗按钮识别的 60 秒期限。若场次、时长或账号上限先到，则直接回港停止，不再等待或开始下一场。
- 账号档案只保存本地别名和配置覆盖，不保存真实账号、密码、令牌或验证码，也不代登录。切换账号需要用户手动完成，GUI 会等待确认。

账号档案的简洁用法：

```powershell
py -3.14 -m src.main --account alt1
py -3.14 -m src.main --rotate
```

更完整的轮换配置见 `accounts.yaml`、`config.yaml` 和详细设计补充文档。

## 新船校准

脚本通过鼠标滚动和点击在港口船只轮播条中选择目标船。新增船只至少需要船卡模板，确认“已选中”则需要选中态或右侧船名证据。

```powershell
.\wows-tool.cmd calibrate_ship --root . --ship-id <ship_id> --display-name <船名> --screenshot "screenshots\<截图>.png"
```

校准要求：

- `card.png` 用于在轮播条中定位船只，只证明卡片可见，不等于已经选中。
- `selected.png` 应包含该船的身份特征与选中高亮或边框；`selected_name.png` 用于右侧详情面板船名确认。两者任一命中可确认选中。
- `hp_bar.png` 用于确认左下血量属于当前船只。国服通过血量数字“0/”及连续新帧确认死亡，血条长度不能单独授权退出。缺少己方血量身份模板时不授权提前退出。
- 仅有 `card.png` 的船只档案尚不具备选中确认能力；缺少已选中证据时，运行会在选船阶段保守暂停并提示补标定。

GUI 设置页提供船卡导入和标定工具入口，已有工具仍可从命令行使用。当前仓库中可直接使用的示例包括列宁格勒和铁公爵档案。

## 目录结构

```text
config.yaml                全局运行配置
profiles/cn360/            客户端配置、按键、窗口特征和船只档案
profiles/wg_asia/          亚服独立配置、已修正的小地图与待核对模板
profiles/wg_eu/            直营服欧服独立配置与待标定资源
profiles/wg_na/            直营服美服独立配置与待标定资源
maps/<map_id>/             可选地图包（waypoints 模式使用）
src/gui/                   Tkinter 界面、四模块、视图模型和运行控制
src/runtime/               运行服务、会话执行、消息与能力开关
src/navigation/            autopilot 与 water_target 水面候选筛选
src/perception/            截屏、模板匹配、舰船定位和死亡判定
src/execution/             SendInput、输入门禁、输入线程和安全热键
src/state_machine/         状态机、步骤序列和会话控制
src/storage/               SQLite、文本日志和截图管理
src/tools/                 validate、环境检查、标定、录制回放和统计
tests/                     离线测试
data/ logs/ screenshots/   本地运行产物，不纳入 Git
pytest_work/               本地测试记录与发布检查快照，不纳入 Git
docs/plans/                实现与评审计划
design/                    设计文档、GUI 设计和阈值说明
```

日志、数据库、截图和诊断文件只保存在本机，不纳入 Git。账号密码、令牌等凭据不得保存。

## 运行边界

- 单机、单账号、单游戏窗口，固定一艘船。
- 不读取游戏内存，不修改客户端文件，不抓取网络数据，不使用 OCR。
- 不校验信号旗或经济加成卡，不进入装备页修改装备，不售卖或消耗船只与装备。
- 自动巡航依赖截屏识别和模拟输入；图像缺失、窗口状态变化、游戏界面变化和网络延迟都可能使单次操作暂停或重试。
- 自动化使用风险由使用者承担。完整风险与实机假设见[详细设计评审与实现补充](design/详细设计评审与实现补充.md)和相关设计文档。
